# Үнэлгээ: eval set, хэмжүүр, хүлээн авах дүрэм

## Eval set (evalset/)

- **500 асуулт, 8 домэйн.** Домэйнууд: зээлийн багц, зээлийн хүсэлт, эргэн төлөлт, харилцагч ба ажилтан,
  барагдуулалт ба барьцаа, хадгаламж ба гүйлгээ, ерөнхий дэвтэр/AML/трэнд, cross-domain. 300 нь dev, 200 нь test.
  Тоонууд `evalset/MANIFEST.json`-д бий.
- **Ангилал.** Хариулах боломжтой ~75%, хариулах боломжгүй ~12% (PII, байхгүй өгөгдөл, SQL-ийн бус, гадаад мэдлэг,
  ирээдүй, бичих үйлдэл), хоёрдмол ~13% (2–3 тайлбар, `clarification_mn`).
- **Хүндрэл.** Хариулах боломжтой асуултад ~30/50/20 (хялбар/дунд/хүнд), `AUTHORING.md`-ийн rubric-ээр.
- **Хувилбар.** Асуулт бүр кирилл (`question_mn`), латин галиг (`question_latin`) ба англи (`question_en`)
  хувилбартай. Галиг нь хэрэглэгчийн хоёр хэв маягаар (v/u/w ба kh/o/u), заримдаа гар утсаар бичсэн мэт.
  ~16%-д нь код холилдсон (`question_mixed`) хувилбар бий.
- **Хуваалт.** `family` (нэг загвараас гаргасан асуултууд) бүтнээрээ dev эсвэл test-д орно. Домэйн, ангилал, хүндрэл,
  холимог хувилбараар давхаргалж тэнцвэржүүлсэн (`t2s evalset-build`). Жишээний сан (`knowledge/examples.jsonl`,
  160) eval-д ордоггүй. Eval асуулттай ойролцоо байдлыг MANIFEST-д шалгаж тайлагнасан.
- **Gold SQL.** Хоёр шатлалаар шалгагдсан:
  1. Зохиогч бичиж `check-gold`-оор шалгасан: guard, bot эрхээр ажиллах, хоосон биш, LIMIT-д тэнцүү утга
     (tie) байхгүй, хоёрдмол асуултын тайлбарууд өөр үр дүнтэй.
  2. Бие даасан хоёр дахь хянагч шалгасан. Тайлан ба засварын шийдвэр: `docs/review/evalset/REVIEW_LOG.md`.

  Мөн 8 test-suite DB дээр алдаагүй ажиллана.
- **Нэр томьёоны дүрэм.** Хариулах боломжтой асуулт хоёрдмол үгийг тайлбаргүй хэрэглэхгүй. Тайлбаргүй хэлбэрийг
  зөвхөн хоёрдмол асуултад ашиглана:

  | Тайлбаргүй үг | Хариулах боломжтой асуултад |
  |---|---|
  | «хугацаа хэтэрсэн» | «(1+ хоног)» нэмнэ |
  | «идэвхтэй зээл» | «идэвхтэй багцын» болгоно |
  | «хүүгийн орлого» | «ерөнхий дэвтэрт бүртгэсэн» нэмнэ |

## Run-ийн JSONL талбар

Нэг мөр нь (асуулт × хувилбар × seed). Үндсэн талбарууд:

- **Тохиргоо ба асуулт:** `question_id`, `config_id`, `model`, `split`, `variant`, `seed`, `category`, `difficulty`,
  `domain`, `contains_value`, `tags`, `question`, `question_used` (A4 орчуулга), `sql`, `status`.
- **Үр дүн:** `result_hash`, `row_count`, `correct`, `strict_correct`, `raw_correct` (татгалзалтыг үл тооцсон),
  `soft_f1`, `exec_ok`, `empty`, `error_stage` (extract | guard | exec | empty | llm), `error`.
- **Санал хураалт:** `confidence` (санал нэгдэл), `unanimous`, `n_candidates`, `cand_hashes`, `cand_sqls`,
  `cand_correct`.
- **Зардал:** `repairs`, `agent_steps`, `latency_ms`, `gen_ms`, `prompt_tokens`, `completion_tokens`.
- **Бусад:** `retrieval` (хүснэгт, утга, нэр томьёо, жишээ), `raw_output`, `ts_correct` (`ts-score`-ийн дараа).
- **Хувилбарын мэдээлэл:** `eval_set`, `db_snapshot`, `prompt_version`, `model_revision`, `code_version`.

`.meta.json`-д run-ийн бүрэн мета хадгалагдана: тохиргооны fingerprint, eval set-ийн sha1, DB-ийн fingerprint,
vLLM-ийн хаяг, served model, токены нийлбэр.

## Хэмжүүр (eval/metrics.py)

- **EX (гол).** Кирилл dev дээр, зөвхөн хариулах боломжтой асуултаар тооцно. Гүйцэтгэлийн үр дүнг дараах дүрмээр
  харьцуулна:
  - Баганын дараалал хамаарахгүй.
  - Мөрийн дараалал зөвхөн `order_matters` үед чухал.
  - Тоог 0.01 абсолют, 1e-6 харьцангуй хүлцлээр харьцуулна.
  - Огноо ба timestamp-ийг хэвийн болгоно.
- **Уян дүрслэл (`correct`).** Ижил утгыг өөр хэлбэрээр гаргасныг зөвшөөрнө:
  - Сарын эхний огноо ↔ 'YYYY-MM' ↔ нэг жилийн доторх сарын дугаар; улирал, жил мөн адил.
  - Нэг хэмжээсийн код ↔ нэр (`segment_code` ↔ `segment_name`). Map-ийг DB-ээс автоматаар бүрдүүлнэ
    (`compare.build_code_maps`).

  Хатуу хувилбарыг `strict_correct` / `ex_strict`-д тусад нь гаргана.
- **TS-EX.** EX-ээр зөв бичлэгийг 8 test-suite DB бүр дээр дахин шалгана (`t2s ts-score`). TS-EX ≤ EX.
- **Бусад хэмжүүр.**
  - Soft-F1 (BIRD mini-dev маягаар). Ижил мөрүүдийг эхлээд multiset-ээр тааруулна; үлдсэн мөрийн хос 4 сая-аас олон
    бол (20k × 20k) хэсэгчилсэн оноо өгөхгүй (туслах хэмжүүр, EX-д нөлөөгүй). Өмнөх хувилбартай Soft-F1-ийг харьцуулахгүй
    (`code_version`-оор ялгагдана).
  - Хоосон gold ба хоосон таамаг тэнцүү (BIRD-ийн set дүрэм, баганын тоо хамаарахгүй). ББСБ-ийн eval set-д хоосон gold
    байхгүй (check-gold алдаа). Нөлөөлөх газар: thesis benchmark-ийн `gold_empty` кейс, test-suite-ийн хуулбар DB дээр
    хоосон болсон gold, BIRD сургалтын reward (BIRD-ийн set дүрэмтэй нийцнэ).
  - Задаргаа: хүндрэл, домэйн, утга агуулсан эсэх, tag.
  - Гүйцэтгэгдэх SQL % ба хоосон үр дүн %.
  - Coverage ба selective accuracy.
  - TrustSQL (c = 1, 5, 10). Зөв хариулт ба зөв татгалзалт +1, хариулах боломжтой асуултаас татгалзвал 0, буруу
    хариулт эсвэл хариулах боломжгүй асуултад хариулбал −c. Хоёрдмол асуултыг тодруулсан эсвэл аль нэг тайлбартай
    таарвал +1.
    - Төлөв (`status`): `answered`, `error`, `refused`, `abstained` (E3), `clarify`. Загвар SQL-гүй бүрэн хариу өгвөл
      (`security/sql_guard.is_refusal`: think хаагдсан, эцсийн хариунд SQL-ийн шинж алга) `refused` = хариулаагүй
      (`error_stage = refusal`; E1 ба agent засуулахгүй). Тасарсан гаралт эсвэл SQL олдоогүй форматын алдаа нь `error`
      (`extract`) хэвээр бөгөөд TrustSQL-д хариулсанд тооцогдоно.
  - Хариулах боломжгүйг илрүүлсэн %.
  - Хоёрдмол асуултын тайлбартай таарсан %.
  - Санал нэгдлийн хувь ба тухайн үеийн нарийвчлал, oracle@8.
  - Татгалзалтын муруй (E3).
  - p50/p95 хугацаа, токен, үүсгэх секунд.
  - Bootstrap-аар 95% CI.
- **Seed.** Sampling-тай run (E2) 3 seed-ээр ажиллана. Тайланд дундаж ± std гарна. McNemar-д асуулт бүрийн олонхын
  санал ашиглагдана.

## Хүлээн авах дүрэм (тайлангийн «Төлөв»)

Тохиргоо бүрийг `base`-тай нь (эсвэл `compare_to`) хос асуулт дээр exact McNemar тестээр харьцуулна. Хүлээн авах
нөхцөл:

1. Dev дээрх өсөлт p < 0.05.
2. Англи ба латин хувилбар 2 пунктээс илүү буураагүй (тэдгээр хувилбарыг ажиллуулсан бол).
3. p95 хугацаа `eval.latency_budget_p95_ms`-д (30 с) багтсан.

Жишээ: 300 асуултад 30 зөрүүтэй хос байвал шинэ тохиргоо ≥ 11-ээр илүү ялах ёстой (≈ +3.7 пункт).

## Алдааны шинжилгээ

```bash
t2s errors --file results/runs/dev/B5/arctic-r1-7b__mn__s0.jsonl --n 50     # → results/errors/*.csv
# CSV-ийн manual_nl2sql_bugs, manual_mn_tags баганыг шинжээч бөглөнө, дараа нь:
t2s errors --summary-csv results/errors/B5__arctic-r1-7b__mn__s0.csv
```

Автомат шошго (gold ба таамгийн AST-ийн харьцуулалт) нь зөвхөн санал. Ангиллууд:
- **NL2SQL-BUGs:** 9 ангилал, 31 дэд ангилал.
- **Монгол шошго:** утгын бичлэг, дагавар, галиг, нэр томьёо, буруу хүснэгт, мөн огноо, валют, dialect.

## LLM judge (туслах)

`t2s judge --file <run.jsonl>` нь EX-ээр буруу бичлэгийг judge загвараар дахин үнэлнэ. Judge-ийг тайланд ашиглахын
өмнө дор хаяж 200 хүний шошготой тулгана:
`t2s judge-validate --judge-file ... --human-csv labels.csv`. Шалгуур нь Cohen's κ ≥ 0.8. Гол хэмжүүр EX хэвээр.

## Harness шалгах

`t2s eval --run A6 --model arctic-r1-7b --oracle` нь gold SQL-ийг загварын протоколоор буцаадаг mock LLM ашиглана.
Хариулах боломжтой бүх асуулт 100% зөв гарах ёстой. Энэ шалгалт runner, гүйцэтгэл, харьцуулалтыг загваргүйгээр
баталгаажуулна.
