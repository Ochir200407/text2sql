| `--headline ID` | урьдчилан зарласан гол тохиргоо (test), анхдагч preset-ийнх: V26 `M1ens` (docs/ACCURACY_PLAN.md), V27 — байхгүй |

## Олдог хэлбэрүүд
| Хэлбэр | Жишээ | Split |
|---|---|---|
| Бүтэн JSONL | `results/test/M1ens/arctic-r1-7b__mn__s0.jsonl` (+ `.summary.json`, `.meta.json`) | мөрийн `split` талбар; үгүй бол замд `test`/`dev`, байхгүй бол dev (`results/M1ensp/...`) |
| Товч | `*_kaggle_q.txt` (`compact_results.py`-ийн `Q|id|category|status|correct|conf|cand`) | замд `test`/`dev`, үгүй бол мөрийн тоо (200 → test, 300 → dev) |
| Notebook-ийн лог | `.txt`/`.log` доторх `[compact] results/runs/<split>/<ID>/... n=..` толгой + `Q|` мөрүүд (угтвартай байж болно) | толгойн замаас |
| Зөв id-ийн жагсаалт **†** | `*_answerable_correct.txt` | замаас; зөвхөн хариулах боломжтой дээр, бүрэн эсэх нь шалгагдахгүй (доор) |

(split, ID) бүрд нэг run-ийг ийм дарааллаар сонгоно:
1. **Эх сурвалж:** `--src` > төслийн `results/runs/` — шинэ гаралтыг хуучин локал файл (жишээ нь хуучин JSONL) хэзээ ч давахгүй.
   Локал хувилбарыг алгасвал «төслийн хуучин jsonl-ийг ашиглаагүй: src давуу» гэж хэвлэнэ.
2. Шалгалтаар бүрэн гэж батлагдсан > бусад (зөв id-ийн жагсаалт хэзээ ч батлагдахгүй).
3. Хэлбэр: JSONL > товч > зөв id; дараа нь `__s0`, мөрийн тоо.

Хос харьцуулалтын дутуу талыг (жишээ нь test `M1a`, `I3t`) төслийн `results/runs/`-ээс нөхнө. Товч хэлбэрт түвшин/домэйн
байхгүй тул ижил split-ийн дурын бүтэн JSONL-ээс `question_id`-аар нөхнө.

## Шалгалт ба хасалт
- **JSONL/товч:** мөрийн тоо (dev 300, test 200) ба ангилал (хариулах/боломжгүй/хоёрдмол: dev 224/38/38, test 151/24/25).
  Таарахгүй бол `--force`-гүй: хуулахгүй, **статистик, McNemar, LaTeX, headline, PICK_TEST-д оруулахгүй**, шалтгааныг
  хэвлэнэ (stdout ба RESULTS_<tag>.md-ийн «Хасагдсан run-ууд»); хос нь «хасагдсан M1ens (мөр 180 ≠ 200)» гэж харагдана.
- **`--force`:** хуулж, **«*»** тэмдэгтэй оруулна — n нь бодит мөрийн тоо (LaTeX-ийн «/200» толгойтой зөрөхийг тайлбар мөрөөр
  тэмдэглэнэ), McNemar нь давхцсан асуулт дээр «зөвхөн давхцсан N асуулт» тэмдэглэлтэй. PICK_TEST шийдвэр дутуу run дээр
  гарахгүй.
- **Зөв id-ийн жагсаалт (†):** дутуу асуултыг харуулдаггүй тул дутуу жагсаалт ч шалгалт давна — иймээс бүрэн эсэх нь
  шалгагдахгүй гэж үзнэ: зөвхөн хариулах боломжтой асуулт дээр, **нийт EX ба нийт McNemar-д хэзээ ч ашиглахгүй**, гаралт
  бүрт (stdout, md, LaTeX `$^{\dagger}$`, слайд) тэмдэглэнэ. Шалгах зүйл нь зөвхөн: ижил split-ийн мета бүрэн (хариулах
  224/151) ба id бүр мэдэгдэх хариулах асуулт эсэх.
- Байгаа файлыг `--force`-гүй дарахгүй (ижил бол «ижил» гэж бичнэ). Товч → `results/runs/<split>/<ID>/<ID>_kaggle_q.txt`
  (лог-ийн угтваргүй `Q|` мөрүүд; `results/runs/<split>/<ID>_kaggle_q.txt` аль хэдийн байвал алгасна).

## Тооцоо
- EX = зөв / нийт; ангилал бүр; түвшин ба домэйн — **хариулах боломжтой** дээр (`summary.json`-ийн `by_difficulty`-тэй ижил).
- **CI бүр Wilson score 95% интервал** (z = 1.96); хүснэгтийн толгой/хэсгийн гарчигт «Wilson 95% CI» гэж нэрлэнэ.
- **«Үргэлж тодруулах (суурь)» мөр** (stdout, md, LaTeX): асуулт бүрт тодруулга асуувал хариулах боломжгүй ба хоёрдмол
  бүгд зөв, хариулах боломжтой бүгд буруу — test 49/200 (24.5%, CI 19.1–30.9), dev 76/300 (25.3%).
- McNemar exact: b = A буруу/B зөв, c = A зөв/B буруу, p = min(1, 2·P(X ≤ min(b,c))), X ~ Bin(b+c, ½).
  **Нийт McNemar бүрийн хажууд** хариулах боломжтой асуулт дээрх McNemar ба ангилал бүрийн +b/−c тоо (ангиллын мөрөнд
  p-гүй — урьдчилан зарласан тест нь «нийт» ба «хариулах»).
- p-утга 3 тэмдэгт цифрээр: 0.117, 0.00635, 8.62e-04, 1.05e-11 (жижиг p «0.0» болохгүй); LaTeX-д $8.62 \times 10^{-4}$.
- Хосууд (V26) — test: M1a→M1r, M1a→M1ens, M1a→M1ensr, I3t→M1ensr (I3t байвал), M1ens→M1ensr; dev: M1ens→M1ensp,
  M1ensr→M1enspr; V27 — доорх «V27 preset»; нэмэлтээр `--pair`.

## Headline
Гол үр дүн нь **урьдчилан зарласан** тохиргоо (`--headline`, анхдагч `M1ens`) — test дээр хамгийн өндрийг сонгохгүй. Тэр run
алга эсвэл хасагдсан бол «headline хэвлэхгүй (хамгийн өндрөөр орлуулахгүй)». Max-д суурилсан цорын ганц мөр нь EX хэсэгт
«post hoc (… headline биш, нотолгоо биш)» шошготой.

## Sensitivity (`--exclude-ids`)

(нийт, хариулах; Wilson CI-тэй) ба хос бүрийн McNemar-ийг (нийт, хариулах) **бүгд → хассан** хэлбэрээр хэвлэнэ; аль ч run-д
байхгүй id-г анхааруулна.

## Шийдвэр (V26; docs/ACCURACY_PLAN.md)
`PICK_TEST=1` зөвхөн dev-ийн **хариулах** асуулт дээр M1ensp нь M1ens-ээс ахисан (b > c) ба p < 0.05 үед. Үгүй бол 0
(аль нэг run алга/хасагдсан/дутуу бол мөн 0). Нэг тал нь зөв id-ийн жагсаалт бол шийдвэрт «†» тэмдэглэл нэмнэ.
Env-ийн хэсгийг хэвлэж, `docs/RESULTS_V26.md`-д бичнэ — `config/kaggle_overrides*.env`-д гараар нэмнэ.

- Хосууд (dev): M1ensx0→M1ensx, M1ensxr0→M1ensxr (run_plan `ensx`: M1ens/M1ensr-ийн жор ИЖИЛ сессийн кодоор — шинэ суурь);
  M1a→шинэ үүсгэгч бүр (M1ip, M1fs, M1vf, M1rt, M1cte, M1th, M1dec); M1ens→M1ensx0 — кодын зөрүүг шалгах (V26-ийн код ↔

- **«§» in-sample:** M1ensra (abstain v2-ийн `DEFAULT_WEIGHTS` бүх dev дээр сургагдсан) — EX хүснэгтэд «§»-тэй лавлагаа л,
  McNemar хос ба шийдвэрт ороогүй (`--pair`-ээр гараар нэмбэл «§» тэмдэглэлтэй).
- Шийдвэр: dev-ийн **хариулах** асуулт дээр M1ensx нь M1ensx0-оос ахисан (b > c) ба p < 0.05 бол шинэ гишүүдийг V28-ийн
  эцсийн test-д нэг удаа нэмнэ; үгүй (эсвэл run алга/хасагдсан/дутуу) бол M1ens хэвээр. Env-ийн хэсэг нь зөвхөн тайлбар

- Headline байхгүй; тайланд зөвхөн dev (бусад split-ийн run хуулагдана, гэхдээ тайлагнахгүй); LaTeX/слайдын текст гаргахгүй.

## Холбоотой засвар (`src/mn_text2sql/eval/`)
- `metrics.mcnemar`: `p_value`-г бөөрөнхийлөхгүй (өмнө нь `round(p, 5)` → 1.05e-11 нь 0.0); хэвлэхдээ `metrics.fmt_p`
  (3 тэмдэгт цифр). `report.verdict`-ийн тэмдэглэл үүнийг ашиглана.
- `report.derive_abstention`: тодруулга/татгалзалтад шилжсэн бичлэгийн `strict_correct`-ийг дахин тооцно
  (runner-тэй ижил: хариулах боломжгүйд = correct, бусдад correct ∧ хатуу таарал). Өмнө нь хуучирсан тул E3c-ийн
  `ex_strict` 44.2 > `ex` 39.29 гарч байсан; дахин гаргахад 39.29.
