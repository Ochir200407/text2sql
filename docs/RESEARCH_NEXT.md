# 60%-иас 70% руу: дараагийн алхмын судалгаа (2026-10-29)

Эх: `docs/SQL_QUALITY_AND_GAP.md`, `docs/ACCURACY_PLAN.md`, `report_diplom/Chapters/Ch1_Related.tex`, `report_diplom/references.bib`,
мөн 2026-10-29-нд нээж уншсан arXiv / ACL Anthology хуудсууд. Шинэ ишлэлийн BibTeX нь `docs/research_refs.bib`-д байна
(түлхүүрийг `[...]` дотор бичив). Хуудсыг нээгээгүй, зөвхөн хайлтын үр дүнгээс харсан мэдээллийг **(баталгаагүй)** гэж тэмдэглэв.

**Эхлэх цэг.** Test 200: одоо 101 (50.5%). V26-ийн чуулга + дүрэм + хос харьцуулалтын дараа ≈117–123 (≈60%) гэж таамагласан.
70% = 140 гэдэг нь **+17…23 асуулт** дутуу гэсэн үг. Сул хэсгүүд: cross-domain 2/18, хүнд 11/31, CTE 5/21, харьцаа 15/41,
хариулах боломжгүй 6/24. Алдааны 30–40% нь schema linking, ~22–25% нь шүүлтийн нөхцөл, 15–22% нь агрегат.

**Нэг чухал анхааруулга.** Бусад ажлын ахицыг BIRD дээр хэмжсэн. BIRD dev 1 534 асуулттай, манай test 200 асуулттай. +3 хувийн
ахиц BIRD дээр ~46 асуулт, манайд ~6 асуулт. Манай 95%-ийн итгэлийн завсар ±7 хувь тул нэг аргын +2…3 хувь McNemar-аар
батлагдахгүй байж болно. Доорх «хүлээгдэх ахиц» нь **таамаг**, хэмжилт биш.

## 2. Хоёр Kaggle сесст багтах 3 алхмын төлөвлөгөө

Дүрэм: аргыг **зөвхөн dev дээр** сонгоно, test-ийн SQL-ийг үүсгэж хадгална, оноог **эцэст нь нэг удаа** хэмжинэ
(`SQL_QUALITY_AND_GAP.md` §4-ийн шударга байдлын нөхцөл).

### Алхам 1 — Хариулах боломжгүй/хоёрдмол асуултыг таних ангилагч (сесс A-д өгөгдөл, сургалт CPU дээр)
- Сесс A: M1a-ийн prompt-оор dev 300 + test 200 асуултын Arctic-ийн сүүлийн давхаргын дундаж hidden state, эхний
  токенуудын logprob/entropy, 8 хувилбарын санал зөрөлт (үр дүнгийн бүлгийн тоо), хоосон/NULL үр дүнгийн хувийг хадгална.
- CPU: logistic regression / жижиг MLP-г dev-ийн 3 ангиллаар (хариулах / боломжгүй / хоёрдмол) 5-fold-оор сургана. Нэмэлтээр
  синтетик боломжгүй асуулт (PII, ирээдүй, бичих үйлдэл, гадаад мэдлэг, байхгүй багана) 100–200-г үүсгэнэ. Одоогийн түлхүүр
  үгийн дүрэмтэй OR/AND хослолыг dev дээр сонгоно. Босгыг «хариулах боломжтой асуултын буруу татгалзалт ≤ 2%» байхаар тогтооно.
- Хүлээгдэх ахиц: **+3…+7 асуулт** (боломжгүй 12–15 → 16–19, хоёрдмол +0…2).

### Алхам 2 — Backward schema linking + FK зам + CTE генератор (сесс A, ≈2.5–3 цаг)
- 8 хувилбарын SQL-ээс (sqlglot) хүснэгтийн нэгдлийг гаргаж, FK графын хамгийн богино замаар холбох хүснэгтийг нэмнэ
  (SchemaGraphSQL/RSL-SQL-ийн санаа). Өргөтгөсөн схемээр нэг удаа дахин генерац хийнэ (temperature 0 + 4 хувилбар).
- Хүнд/cross/харьцааны асуултад зориулсан «эхлээд CTE-ээр задал» гэсэн нэмэлт prompt-ын генератор (4 хувилбар).
- Хоёр шинэ генераторыг одоогийн M1ens-ийн чуулгад нэмнэ. Хувилбарын олонлог өргөсөх тул oracle-ийг dev дээр дахин хэмжинэ.
- Хүлээгдэх ахиц: **+3…+7 асуулт** (cross, CTE, хүнд). Хэрэв dev дээр oracle өсөөд чуулга өсөхгүй бол алхам 3 үүнийг ашиглана.

### Алхам 3 — Сургасан хос сонгогч (сесс B, ≈3 цаг)
- Сургалтын өгөгдөл: dev биш, **синтетик асуулт** (M1i4-ийн 475 + алхам 1-ийн синтетик) дээр 8–16 хувилбар үүсгэнэ. Гүйцэтгэлийн
  үр дүнгээр (зөв / буруу) хос үүсгэнэ, A/B ба B/A хоёр дарааллаар (байрлалын хазайлтаас сэргийлэх), ~2–4 мянган хос.
- Arctic-7B дээр (эсвэл хурдны тулд Qwen2.5-Coder-1.5B дээр) QLoRA-аар нэг эпох сургана. XiYan-ийн «candidate reorganization»
  санааг хэрэглэнэ: эхлээд үр дүнгээр бүлэглэж, зөвхөн шилдэг 2–3 бүлгийг харьцуулна.
- Dev дээр M1ens-тэй McNemar-аар харьцуулна. Ахисан тохиолдолд л test-д ашиглана.
- Хүлээгдэх ахиц: **+2…+6 асуулт.**

## 4. Дипломд гаргаж болох ба болохгүй мэдэгдэл

### Гаргаж болох (нотолгоотой)
1. «Бидний хайлтаар (2026-10) монгол хэлний Text2SQL-ийн нийтэд нээлттэй сан, систем олдсонгүй.» (Хайлтын хүрээг заах.)
2. «Нэг DB дээр орчуулга, RAG, сургалт, санал хураалт, чуулгын нөлөөг тус тусад нь McNemar-аар хэмжсэн.» (p утгатай.)
3. «Олон хувилбар + сонголт нь self-consistency-оос илүү гэдгийг BIRD дээр CHASE-SQL (+4.2), XiYan-SQL (+3.1), JudgeSQL
   (+3.33 дундаж) харуулсан. Манай чуулгын ахиц (dev +11/−1, p = 0.006) энэ чиг хандлагатай нийцтэй.»
4. «Бага нөөцтэй хэлний Text2SQL-д англи бус асуулт нарийвчлалыг бууруулдаг (MultiSpider 2.0, BIRDTurk, BIRD_PT).»
5. «7B нээлттэй загвар + 3B орчуулагч нэг GPU дээр ажиллана.» (Өөрийн хэмжилт.)
6. «Test дээр 50.5% EX (хариулах боломжтой 53.6%).» V26-ийн дараа хэмжсэн бодит тоо.

### Гаргаж БОЛОХГҮЙ
1. «BIRD/Spider-ийн үр дүнтэй шууд харьцуулж болно.» Манай DB нэг, синтетик, test 200, татгалзалтыг оноонд оруулдаг тул
   харьцуулах боломжгүй.
2. «70%-д хүрсэн» эсвэл «70%-д хүрнэ». Test дээр нэг удаа хэмжээгүй бол болохгүй. Dev-ийн 65.7%-ийг test-ийн үр дүн гэж
   танилцуулахгүй.
3. «X арга манайд +N хувь өгнө» гэж бусад ажлын BIRD-ийн тоог шилжүүлэх. Энэ нь зөвхөн таамаг.
4. «Монгол хэлэнд шилдэг (state of the art)». Харьцуулах өөр систем байхгүй тул утгагүй мэдэгдэл.
5. «Нэр томьёоны reranker / M1g8 / M1ks тус бүр ахиц өгсөн». Статистик батлагдаагүй (p = 0.5–1.0).
6. «Бодит ББСБ-ийн өгөгдөл дээр ажиллана». DB синтетик, бодит хэрэглэгчийн асуулт байхгүй.
7. «Schema linking жижиг загварт заавал тустай». Нотолгоо зөрчилтэй (RSL-SQL: EX +1.2; Maamari нар; Beskorovainyi).
8. Хуудсыг нь нээж шалгаагүй ажлын тоо (жишээ нь CMiLBench, R³-SQL) — зөвхөн «(баталгаагүй)» гэж.
