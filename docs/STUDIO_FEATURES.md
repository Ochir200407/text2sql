# Studio ба асуулт-хариултын хуудасны шинжээчийн боломжууд

Studio (`/builder` → 💬 Emulator) ба шинжээчийн хуудас (`/`, `POST /ask`) хоёуланд нь ажиллана. Бүх боломж
**нэмэлт LLM дуудахгүй**, өгөгдлийн санд дахин хандахгүй: хариулт гарах үед байгаа мэдээллээс (SQL-ийн AST, санал
нийлэлт, гүйцэтгэлийн үр дүн) детерминистээр тооцоолно.

| Файл | Үүрэг |
|---|---|
| `src/mn_text2sql/service/analyst.py` | Тооцоолол (тайлбар, итгэл, мэдэгдэл, график, CSV/XLSX, үнэлгээ) ба `/analyst/*` endpoint |
| `src/mn_text2sql/service/static/analyst.js` | Хоёр хуудсанд дундаа хэрэглэх харагдац (гадны сан, CDN-гүй) |
| `flow.py`, `api.py` | Хариултад `analyst` талбар нэмэх, router холбох (нэмэлт хэдхэн мөр) |
| `tests/test_service_analyst*.py` | PG, GPU-гүй unit тест (25) |

Хариултын JSON-д шинэ `analyst` талбар нэмэгдэнэ:
`{rid, sql_explain, confidence, notices, chart, export, xlsx, feedback}`. Энэ хэсэгт алдаа гарвал `{error}` буцаадаг тул
үндсэн хариулт тасалдахгүй.

---

## 1. SQL-ийн монгол тайлбар («🧾 SQL юу хийдэг вэ»)

Үүссэн SQL-ийг `sqlglot` (postgres) ашиглан задлаад semantic model-ийн монгол нэрээр дараах хэсгүүдийг харуулна:

- **Хүснэгт**: жишээ нь «Зээл (loans)». Олон хүснэгт бол JOIN-оор холбосныг заана.
- **Шүүлт**: «Төлөв нь «ACTIVE»», «Олгосон огноо ≥ «2026-06-01»», `IN`, `BETWEEN`, `LIKE`, `IS NULL`, `EXTRACT(YEAR …)`.
- **Бүлэглэлт**, **Тооцоо** (нийлбэр, дундаж, тоо, давхардалгүй тоо, хамгийн их/бага), **Бүлгийн шүүлт** (HAVING).
- **Эрэмбэ**: өсөхөөр эсвэл буурахаар.
- **Хязгаар**: эхний N мөр. Guard-ын хүчээр нэмсэн LIMIT бол «хамгаалалтын дээд хязгаар» гэж харуулна.

**Хэрэглэх**: хариултын доорх «🧾 SQL юу хийдэг вэ»-г нээнэ. Тайлбарыг асуулттайгаа тулгаж SQL зөв ойлгосон эсэхийг
шалгана.

**Хязгаарлалт**: зөвхөн гаднах SELECT-ийг дэлгэрэнгүй тайлбарлана. CTE эсвэл subquery байвал «Анхаар» мөр нэмэгдэнэ.
Нийлмэл илэрхийллийг (CASE, цонхны функц) SQL текстээр нь богиносгож харуулна. Монгол нэр нь semantic model-д
байхгүй баганын англи нэр хэвээр үлдэнэ. Тайлбар нь SQL-ийн бүтцийг хэлдэг. SQL нь асуултад зөв хариулж буй эсэхийг
баталгаажуулахгүй.

## 2. Итгэлийн түвшин ба татгалзсан шалтгаан

«Итгэл: өндөр / дунд / бага / тодорхойгүй» шошго болон шалтгааныг энгийн монголоор харуулна.

- **Өндөр**: бүх хувилбар ижил үр дүн өгсөн, эсвэл санал нийлэлт ≥ 80%. **Дунд**: 50–80%. **Бага**: 50%-иас бага.
- **Тодорхойгүй**: нэг л хувилбар үүсгэсэн тохиргоо. Санал хураалтгүй тул 100% гэдэг тоо төөрөгдүүлэх тул ингэж харуулна.
- **Татгалзсан**: юу болсныг тайлбарлана. Шүүлтээр зогссон (өгөгдөл өөрчлөх, хувийн мэдээлэл), загвар SQL бичээгүй,
  эсвэл SQL guard-д тэнцээгүй.
- **Тодруулга** ба **итгэл бага**: хувилбарууд өөр үр дүн өгсөн эсвэл SQL алдаатай байсан. Асуултаа хэрхэн
  тодруулахыг (хугацаа, хэмжигдэхүүн, шүүлт) зөвлөнө.

**Хязгаарлалт**: итгэл нь хувилбаруудын санал нийлэлт бөгөөд зөв байх магадлал биш. Бүх хувилбар ижил алдаа гаргаж болно.

## 3. Мөрийн хязгаар ба timeout-ийн мэдэгдэл

- Үр дүн `security.enforce_limit` (1000) мөрд хүрвэл «бүрэн биш байж болно» гэж анхааруулна.
- Дэлгэцэнд хэдэн мөр харуулснаа заана: Studio 20, `/` хуудас 200 мөр. Бүгдийг CSV/Excel-ээр татахыг санал болгоно.
- `statement_timeout`-оор (20 с) зогссон эсвэл EXPLAIN өртөг хэт өндөр бол улаан мэдэгдэл гаргаж, асуултыг
  нарийсгахыг зөвлөнө.

## 4. Автомат график (📊)

Үр дүнгийн баганын төрлөөс (тоон, огноо/он/сар, ангилал, `*_id`/код) автоматаар сонгоно:

- **Line**: хугацааны 1 багана + тоон багана, 3–200 цэг. Хугацааны дарааллаар эрэмбэлнэ.
- **Bar**: ангиллын 1 багана + тоон багана, 2–30 давхардаагүй ангилал. Тэнхлэг 0-ээс эхэлнэ.
- **График гаргахгүй**: 1 мөр, тоон багана байхгүй, ангиллын багана 2-оос олон, ангилал хэт олон гэх мэт тохиолдолд.

Inline SVG-ээр зурна (шинэ сан, CDN нэмээгүй). Мөр бүр дээр хулганаа барихад утга нь харагдана.

**Хязгаарлалт**: нэг хэмжигдэхүүн, нэг тэнхлэг зурна (хоёр масштабыг холихгүй). Бусад тоон баганыг хүснэгтээс харна.
Цэгүүд серверийн бүрэн үр дүнгээс (≤ 1000 мөр) ирдэг тул хариултын хэмжээ бага зэрэг өснө.

## 5. CSV ба Excel татах (⤓)

- `GET /analyst/export/{rid}?fmt=csv|xlsx[&k=…]` бүрэн үр дүнг татна (≤ 1000 мөр, дэлгэцийн 20/200-аар
  хязгаарлагдахгүй).
- CSV: UTF-8 BOM-той тул Excel кирилл үсгийг зөв уншина.
- XLSX: `openpyxl` (3.1.5 суусан) ашиглана. «Үр дүн» хуудас, асуулт ба SQL бүхий «SQL» хуудастай. Суугаагүй бол
  Excel товч харагдахгүй.
- **Аюулгүй байдал**: `=`, `+`, `-`, `@` тэмдэгтээр эхэлсэн текст нүдэнд `'` нэмж Excel-ийн томьёо шахалтаас
  хамгаална. Сөрөг тоо хэвээр үлдэнэ.

**Хязгаарлалт**: үр дүн серверийн санах ойд 1 цаг, хамгийн ихдээ сүүлийн 64 хариулт хадгалагдана. Сервер дахин
эхэлбэл экспорт 404 өгнө. Тэр үед асуултаа дахин ажиллуулна. `shadow` горимд үр дүнг кэшлэхгүй, экспорт хийхгүй.

## 6. Асуултын түүх ба дахин ажиллуулах (🕘)

- Studio: Emulator-ын толгойн «🕘 Түүх» товч. `/` хуудас: «Өмнөх асуултууд» хэсэг. Асуулт дээр дарахад дахин
  илгээнэ.
- Сүүлийн 30 асуултыг статусын тэмдэгтэй (✓ ⛔ ❓ 🤔) хадгална.

**Хязгаарлалт**: зөвхөн тухайн хөтчийн `localStorage`-д хадгалагдана. Сервер рүү илгээхгүй, бусад төхөөрөмж рүү
шилжихгүй. Private горимд хадгалагдахгүй байж болно. Дахин ажиллуулахад тухайн үеийн тохиргоогоор шинээр бодно.

## 7. 👍/👎 үнэлгээ ба жишээний нэр дэвшигч

- `POST /analyst/feedback {rid, good}`. Сервер асуулт ба SQL-ийг **өөрийн кэшээс** авна. Үйлчлүүлэгчээс SQL хүлээж
  авахгүй тул SQL шахах боломжгүй.
- Санал бүр `build/feedback/studio_votes.jsonl`-д хадгалагдана. Асуултын текстийг биш, зөвхөн hash-ийг бичнэ.
- 👍 авсан **хариулсан** (`answered`) асуулт→SQL хосыг `build/feedback/candidate_examples.jsonl`-д
  `review: "pending"` төлөвтэй нэмнэ (`id`, `question_mn`, `gold_sql`, `tables`). Ижил хосыг давхар нэмэхгүй.
- Хянагч `GET /analyst/candidates?admin=…` (тусдаа `T2S_ADMIN_KEY`; тохируулаагүй бол хаалттай)-ээр файлыг татаж шалгаад, зөвийг нь **гараар**
  `knowledge/examples.jsonl` руу шилжүүлж индексийг дахин бүтээнэ. Систем `knowledge/examples.jsonl` руу **хэзээ ч
  автоматаар бичихгүй**.

**Хязгаарлалт**: нэр дэвшигчийн файлд асуултын текст шифрлэлтгүй хадгалагдана, учир нь хянахад текст хэрэгтэй.
`build/` нь git-д ордоггүй. Асуултад харилцагчийн нэр гэх мэт хувийн мэдээлэл орсон бол хянагч устгана.
`T2S_WEB_KEY` тохируулаагүй бол түлхүүрээр хамгаалагдахгүй (бусад `/flow/*` endpoint-той адил). Хуучин
`POST /feedback` (засварласан SQL, шифрлэсэн тайлбар) хэвээр ажиллана.

## Аюулгүй байдлын баталгаа (өөрчлөгдөөгүй)

- SQL guard, read-only транзакц, `statement_timeout`, EXPLAIN өртгийн хязгаар, audit log өөрчлөгдөөгүй.
- Шинэ endpoint-ууд SQL гүйцэтгэдэггүй бөгөөд үйлчлүүлэгчээс SQL хүлээж авдаггүй. Зөвхөн серверийн кэш дэх үр дүнг
  санамсаргүй 12 оронтой `rid`-аар буцаана. `T2S_WEB_KEY` тохируулсан бол `?k=` түлхүүр шаардана.
- `rid`-ийг зөвхөн hex тэмдэгтээр (`^[0-9a-f]+$`) хүлээж авна.
