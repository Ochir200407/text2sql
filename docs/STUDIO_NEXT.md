## Боломж 1. Баталгаажсан асуулгын сан ✅

**Яагаад.** Cortex Analyst-ийн VQR ба Genie-ийн trusted assets-ийн гол санаа: банкинд «идэвхтэй зээлийн багц»,
«PAR30» гэх мэт байнга асуудаг асуултын **албан ёсны** SQL-ийг админ нэг удаа батлаад, дараа нь шинжээч бүр ижил
хариулт авах. Мөн баталгаажсан хос нь few-shot / RAG жишээний хамгийн чанартай эх үүсвэр (Vanna, Defog).

**UX.**
- Хариултын асуулт баталгаажсан асуулттай таарвал: сонгосон SQL ижил бол ногоон «✅ Админ баталгаажуулсан
  асуулгатай ижил SQL», өөр бол шар «⭐ Төстэй баталгаажсан асуулга: «…» (82%)» + «▶ Баталгаажсан SQL-ийг ажиллуулах»
  товч (LLM-гүй, шууд DB).
- Админ: URL-д `?admin=…` байхад хариулт бүрт «⭐ Баталгаажуулах» товч (серверийн кэш дэх асуулт→SQL-ийг санд нэмнэ).

**Backend** (`service/analyst.py`):
- `VerifiedStore` — `build/feedback/verified_queries.jsonl` (`id=VQ-<8 hex>`, `question_mn`, `gold_sql`, `tables`,
  `source`, `note`, `ts`, `pair_sha`). Нормчилсон асуулт+SQL-ээр давхардал шалгана.
- `match()` — нормчилсон асуулт ижил бол 1.0, бусад нь үгийн язгуурын (эхний 5 үсэг — монгол залгаврыг ойролцоогоор
  хасна) Jaccard ≥ 0.6. `verified_info()` — `same_sql`-ийг sqlglot-оор форматлаад guard-ын нэмсэн `LIMIT`-ийг хасаж
  харьцуулна.
- `build_extras()` хариултын `analyst.verified` талбарт нэмнэ.
- Endpoint:

| Endpoint | Эрх | Үүрэг |
|---|---|---|
| `GET /analyst/verified?k=[&q=]` | хэрэглэгч (`T2S_WEB_KEY`) | Жагсаалт эсвэл асуултаар хайх |
| `POST /analyst/verified?admin=` `{rid}` эсвэл `{question, sql}` (+`note`) | `T2S_ADMIN_KEY` | Санд нэмэх. `rid`-ийн үед асуултыг засаж (хувийн мэдээлэл хасах) болно |
| `DELETE /analyst/verified/{VQ-…}?admin=` | `T2S_ADMIN_KEY` | Устгах |
| `GET /analyst/verified/export?admin=` | `T2S_ADMIN_KEY` | `knowledge/examples.jsonl` хэлбэрээр NDJSON |
| `POST /analyst/verified/{VQ-…}/run?k=` | хэрэглэгч | Баталгаажсан SQL-ийг guard → read-only DB-ээр ажиллуулах |

**Frontend**: `static/analyst.js` (`render` — ✅/⭐ мөр, `bind` — ажиллуулах ба баталгаажуулах товч).

**Өгөгдөл.** `build/` git-д ордоггүй. Асуулт шифрлэгдэхгүй: санг бүх шинжээчид харуулах зорилготой бөгөөд админ
батлахаасаа өмнө хувийн мэдээллийг хасна (👍-ийн нэр дэвшигч шифртэй хэвээр). Систем `knowledge/examples.jsonl`
руу **автоматаар бичихгүй** — админ export-оос хянаад гараар нэмж индексийг дахин бүтээнэ (few-shot/RAG).

**Аюулгүй байдал.** Нэмэх, устгах, export нь зөвхөн `T2S_ADMIN_KEY`-ээр (тохируулаагүй бол хаалттай, `hmac.compare_digest`).
Гаднаас ирсэн SQL-ийг `SqlGuard.check(rewrite=False)`-оор шалгана. Guard байхгүй сервер дээр зөвхөн кэшийн (аль хэдийн
guard-аар орсон) SQL-ийг батална. Ажиллуулах SQL нь үйлчлүүлэгчээс биш, серверийн сангаас ирнэ.

**Тест** (`tests/test_service_analyst_next.py`): нэмэх, давхардал, язгуураар таарах, устгах, export хэлбэр, `same_sql`
(LIMIT-ийг үл тооцох), админ эрх (403), guard-д тэнцээгүй SQL (400), guard-гүй сервер (501), шууд ажиллуулах.

## Боломж 2. SQL засаж дахин ажиллуулах ✅

**Яагаад.** Шинжээч SQL уншиж чаддаг бол загварын «бараг зөв» SQL-ийг (жишээ нь шүүлтийн утга, хугацаа) өөрөө
засаад шууд үр дүн авах нь асуултыг дахин бичихээс хурдан (Vanna, Genie «Show code», ThoughtSpot). Засварласан
зөв SQL-ийг админ дараа нь №1 санд баталж болно.

**UX.** Хариултын доор «✏️ SQL засаж дахин ажиллуулах»: textarea-д үүссэн SQL, «▶ Ажиллуулах». Үр дүн (эхний 50
мөр), хураангуй, график, тайлбар, CSV/Excel, итгэлийн шошго «гараар засварласан» доор нь гарна. Guard-ын алдааг
монголоор харуулна.

**Backend.** `POST /analyst/rerun?k=` `{sql (≤ 8000), rid?}` → `SqlGuard.check()` (нэг SELECT, зөвхөн `t2s` view,
allow-list хүснэгт/багана, хориотой функц, `LIMIT ≤ enforce_limit`, `CURRENT_DATE`→`as_of_date`) → `Executor.run()`
(`set_session(readonly=True)` + `SET TRANSACTION READ ONLY` (2026-10-31; өмнө нь `BEGIN READ ONLY` psycopg2-ийн
transaction дотор нөлөөгүй, зөвхөн role-оор хамгаалагдаж байсан), `statement_timeout`, EXPLAIN өртгийн хязгаар, мөрийн
хязгаар) → шинэ `rid`-тэй ResultCache.
Router нь `FlowRunner`-ийн `guard`, `executor`, `cfg`-ийг ашиглана (`flow.make_router(runner, check_key, audit)`).

**Аюулгүй байдал.**
- Guard-д тэнцээгүй SQL DB-д огт хүрэхгүй (тестээр баталгаажсан: DROP, олон statement, `public.*`, үл мэдэгдэх
  хүснэгт/багана, UPDATE, `pg_sleep`).
- Нээх нөхцөл: `T2S_SQL_EDIT=1` эсвэл тохируулаагүй ба `service.mode != shadow`; `T2S_SQL_EDIT=0` бол үргэлж хаалттай.
  Shadow горимд хэрэглэгчид үр дүн харуулдаггүй тул энэ зам ч хаалттай.
- Нэг процесст зэрэг ≤ 2 (давбал 429). `T2S_WEB_KEY` шаардана.
- Audit: `api.py`-ийн `AuditLog.write` (SQL ба асуулт `T2S_AUDIT_KEY`-ээр шифрлэгдэнэ), татгалзсаныг
  `edited_rejected` статусаар.
- Засварласан хариултын 👍 нь нэр дэвшигч болохгүй (`status="edited"`) — зөвхөн админ №1-ээр батална.

**Тест**: guard-ын LIMIT нэмэгдсэн SQL ажилласан, экспорт, audit, 👍 нэр дэвшигч болохгүй, 7 төрлийн аюултай SQL
(DB дуудалт 0), түлхүүр, урт, `T2S_SQL_EDIT=0`, shadow (403), DB-гүй сервер (501).

**Хүчин чармайлт**: 1 өдөр (хэрэгжсэн).

## Боломж 3. Үр дүнгийн монгол хураангуй (template, LLM-гүй) ✅

**Яагаад.** Power BI-ийн narrative summary, ThoughtSpot Sage-ийн хариултын тайлбар: менежерт хүснэгт биш «гол
дүгнэлт» хэрэгтэй. LLM-ээр бичвэл тоо зохиох эрсдэлтэй тул **тоог зөвхөн үр дүнгээс** тооцоолж загвар өгүүлбэрт
оруулна.

**UX.** Итгэлийн мөрийн дор «📝 Нийт 12 мөр. «Зээлийн үндсэн дүн» хамгийн их нь «УБ-01» (…), хамгийн бага нь …
Нийлбэр …; хамгийн их нь нийлбэрийн 38%-ийг эзэлнэ.»

**Backend.** `summarize_result(columns, rows, labels, row_count, truncated)`:
- 0 мөр → хоосон гэж, шүүлтийг шалгахыг зөвлөнө; 1×1 → «Хариулт: X»; 1 мөр → багана бүр.
- Ангилал + тоо → хамгийн их/бага, нийлбэр ба эзлэх хувь (дундаж/хувь/харьцаа нэртэй баганыг нэмэхгүй, сөрөг утгатай
  бол нийлбэр харуулахгүй).
- Хугацаа + тоо → эхний ба сүүлийн үе, өөрчлөлтийн хувь, оргил үе.
- Хязгаарт хүрсэн бол «бүрэн биш байж болно».
Баганын нэрийг semantic model-ийн монгол нэрээр (хаалтан доторх тайлбаргүй) харуулна.

**Хязгаарлалт**: зөвхөн эхний тоон баганыг хураангуйлна; «яагаад» гэдгийг тайлбарлахгүй.

**Тест**: нэг утга, хоосон, нэг мөр, ангиллын топ/доод/хувь, харьцааны баганыг нэмэхгүй, хугацааны өөрчлөлт.

## Боломж 4. Дараагийн асуулт → жинхэнэ multi-turn ◐

**Яагаад.** Vanna, Genie, Looker, Cortex бүгд дараагийн асуултыг санал болгож, өмнөх асуултын контекстийг хадгалдаг.
Шинжээчийн ажлын урсгал: «нийт дүн» → «салбараар» → «сараар» → «өмнөх онтой».

**1-р шат (хэрэгжсэн, LLM-гүй).** `suggest_followups(question, sql, labels)` SQL-ийн бүтцээс (sqlglot) ≤ 4 санал:
- Нэгтгэл, бүлэглэлтгүй → «Салбар тус бүрээр» (хүснэгтэд `branch_id` байвал), «Сар бүрээр (Олгосон огноо)»,
  ангиллын багана (төлөв, валют, сегмент …) тус бүрээр. Шүүлтэд орсон баганаар дахин задлахгүй.
- Бүлэглэсэн → «Хамгийн их 5» (жижиг LIMIT байхгүй бол), сар бүрийн чиг хандлага, «Нийт дүн (задаргаагүй)».
- Жагсаалт → «Нийт тоо», «Салбар тус бүрийн тоо». Шүүлтэд он байвал «Өмнөх онтой харьцуулах».
Pipeline stateless тул санал бүр **анхны асуултыг агуулсан бүтэн асуулт** («<асуулт> — салбар тус бүрээр задлан
харуулна уу») — контекст алдагдахгүй, pipeline-д өөрчлөлт хэрэггүй. Товч дээр дарахад тухайн асуултыг шууд илгээнэ
(`/` хуудас ба Studio Emulator).

**2-р шат (төлөвлөгөө).** `AskIn`-д `context_rid` нэмж, серверийн кэшээс өмнөх асуулт ба SQL-ийг авна; prompt-д
«Өмнөх асуулт / SQL» хэсэг (`llm/prompts.py`, `pipeline/orchestrator.py` — өөр workstream эзэмшдэг тул тэдэнтэй
зохицуулна). Ярианы урт ≤ 3 алхам, кэшийн TTL 1 цаг. Тест: контексттэй/контекстгүй prompt-ийн snapshot, `context_rid`
байхгүй/хугацаа дууссан (404 биш — контекстгүй үргэлжилнэ). Хүчин чармайлт: 3 өдөр + үнэлгээ (multi-turn dev багц).

## Боломж 5. Тодруулгын UI (төлөвлөгөө)

**Яагаад.** Cortex Analyst хоёрдмол асуултад тодруулсан асуултын хувилбар санал болгодог, Genie тодруулах асуулт
асуудаг. Манай pipeline `clarify` / `abstained` статус ба өөр өөр үр дүн өгсөн хувилбаруудыг аль хэдийн гаргадаг.

**UX.** «❓ Асуултыг хэд хэдэн янзаар ойлгож болно» → хувилбар бүрийн **монгол тайлбар** (`explain_sql`) ба мөрийн
тоо картаар; шинжээч «Энэ утгаар» дарахад тухайн хувилбарын SQL ажиллана, эсвэл зөвлөмжтэй (хугацаа/хэмжигдэхүүн/шүүлт)
дахин асууна.

**Backend.** `build_extras` нь `clarify`-ийн үед ялгаатай үр дүнтэй ≤ 3 хувилбарын SQL-ийг кэшэд
(`rid` → `alts[i]`) хадгална. `POST /analyst/clarify/{rid}/{i}` — SQL-ийг үйлчлүүлэгчээс биш кэшээс авч №2-ын
`execute()`-ээр (guard → read-only) ажиллуулна. Сонголтыг `votes.jsonl`-д hash-аар бичнэ (аль тайлбарыг сонгосон
нь цаашид prompt-ын инструкц/glossary-д ашиглах дохио). **Аюулгүй байдал**: SQL үйлчлүүлэгчээс ирэхгүй, индекс 0–2.
**Тест**: кэшэд хувилбар хадгалагдах, индексийн хил, guard. **Хүчин чармайлт**: 2 өдөр.

## Боломж 6. Схемийн хөтөч (монгол тайлбартай) (төлөвлөгөө)

**Яагаад.** Power BI Q&A-ийн linguistic schema, Genie-ийн data tab: шинжээч ямар өгөгдөл байгааг мэдвэл асуултаа зөв
томьёолно («хадгаламжийн хүү» `deposits.interest_rate` гэдгийг харна).

**UX.** «📚 Өгөгдөл» самбар: хүснэгт бүрийн монгол нэр, тайлбар; баганын монгол нэр, төрөл, жишээ утга (зөвхөн
semantic model-ийн `values`/glossary-аас, DB-ээс биш); хайлт (монгол/англи); баган дээр дарахад нэрийг асуулт руу
оруулна. Мөн баталгаажсан асуулт (№1)-ыг хүснэгтээр бүлэглэж «жишээ асуулт» болгоно.

**Backend.** `GET /analyst/schema?k=` — `cached_model()`-оос `{table, mn, columns: [{name, mn, type}]}`; `pii: true`
баганыг **хасна**, семантик загварт байхгүй хүснэгтийг харуулахгүй. Хариуг ETag-аар кэшлэнэ. **Frontend**: analyst.js-д
`renderSchema(el, onPick)`. **Тест**: PII багана гарахгүй, түлхүүр, хайлт. **Хүчин чармайлт**: 1.5 өдөр.

## Боломж 7. Хадгалсан самбар / pin (төлөвлөгөө)

**Яагаад.** ThoughtSpot Liveboard, Power BI «pin to dashboard», Genie → AI/BI dashboard: өдөр бүр харах KPI-ийг дахин
асуухгүй нэг дэлгэцэд.

**UX.** Хариулт бүрт «📌 Самбарт нэмэх». «📌 Самбар» хуудас: карт бүр — гарчиг, сүүлд шинэчилсэн цаг, хураангуй
(№3), график, «↻ Шинэчлэх» (SQL-ийг дахин ажиллуулна, LLM-гүй).

**Backend/өгөгдөл.** 1-р шат: зөвхөн хөтчийн `localStorage` (түүхтэй адил), картад зөвхөн `VQ-…` id эсвэл админ
батлаагүй бол SQL-ийн hash + асуулт хадгална. Шинэчлэлт нь `/analyst/verified/{id}/run` (баталгаажсан) эсвэл
`/analyst/rerun` (guard-ын ард). 2-р шат: серверийн `build/studio/boards.json` (хэрэглэгчийн hash-аар, `T2S_AUDIT_KEY`-ээр
шифрлэнэ), админы «нийтийн самбар» зөвхөн баталгаажсан асуулгаас. **Аюулгүй байдал**: самбар шинэчлэх нь №2-ын
бүх хязгаар (guard, timeout, мөр, зэрэг ≤ 2)-т захирагдана; нэг дор ≤ 12 карт. **Тест**: хадгалах/устгах, шинэчлэлт
guard-аар, rate limit. **Хүчин чармайлт**: 3 өдөр.
