# Системийн хөгжлийн бүрэн дараалал — Монгол хэлний Text-to-SQL (ББСБ)

Энэ баримт нь системийг анхнаас нь өнөөг хүртэл **алхам алхмаар** тайлбарлана: алхам бүрт юу нэмэгдсэн, **хэрхэн ажилладаг**,
нарийвчлал хэдэн хувиар өөрчлөгдсөн. Тоо бүр `results/runs/`-ийн асуулт бүрийн гаралтаас (эсвэл дипломын Хүснэгт 4.1, 6.1–6.4-өөс).
Хувийн өөрчлөлтийг «хувь» (percentage point) гэж бичив.

---

## 0. Даалгавар, өгөгдөл, хэмжүүр

- **Өгөгдлийн сан.** Банк бус санхүүгийн байгууллагын (ББСБ) синтетик PostgreSQL сан. Bot зөвхөн `t2s` схемийн **28 view**-г
  харна: зээл, эргэн төлөлт, хуваарь, шимтгэл, хадгаламж, данс, гүйлгээ, харилцагч (хувь хүн/байгууллага), зээлийн хүсэлт,
  скоринг, барьцаа, батлан даагч, барагдуулалт (кейс, үйлдэл, амлалт), ерөнхий дэвтэр (GL), AML, ханш. Өгөгдөл 2024-01-01 →
  2026-06-30; «өнөөдөр» = 2026-06-30.
- **Үнэлгээний сан (500 асуулт).** dev 300 (хариулах боломжтой 224 / боломжгүй 38 / хоёрдмол 38), test 200 (151 / 24 / 25).
  Асуулт бүр кирилл, латин галиг, англи хувилбартай, gold SQL нь DB дээр гүйцэтгэж шалгагдсан. dev ба test-ийг «family»-гаар
  (ижил загварын асуултын бүлэг) хуваасан тул ойролцоо асуулт хоёуланд нь орохгүй.
- **Хэмжүүр — EX (execution accuracy).** Системийн SQL-ийн гүйцэтгэлийн үр дүн gold-ийнхтэй (мөрийн олонлог, тоон хүлцэлтэй)
  таарвал зөв. **Хариулах боломжтой EX** нь гол хэмжүүр; **нийт EX**-д хариулах боломжгүй асуултад татгалзах, хоёрдмол асуултад
  тодруулга асуух нь зөвд тооцогдоно.
- **Загвар.** SQL бичигч нь цорын ганц **Arctic-Text2SQL-R1-7B** (Qwen2.5-Coder-7B дээр GRPO-оор сургасан, BIRD dev 68.9%).
  Kaggle-ийн T4×2 дээр vLLM-ээр ажиллана.

## 1. Суурь: Arctic-ийг шууд ашиглах (A бүлэг) — dev **2.3%**

**Хэрхэн ажилладаг.** Arctic-ийн сургалтын (OmniSQL) prompt: түүхий DDL (тайлбаргүй `CREATE TABLE`) + асуулт →
загвар `<think>` дотор бодоод `<answer>` дотор SQL бичнэ. Arctic SQLite дээр сургагдсан тул:

| ID | Тохиргоо | dev нийт |
|---|---|---|
| A1 | Кирилл асуулт, тайлбаргүй схем, SQLite протокол | 4 (1.3%) |
| A2 | A1, гэхдээ **төгс англи** асуулт | 43 (14.3%) |
| A3 | A1, латин галигаар | 0 (0%) |
| A6 | Prompt-д «PostgreSQL ашигла» гэж заах | 6 (2.0%) |
| **A7** | SQLite-аар бичүүлээд **sqlglot**-оор PostgreSQL руу хөрвүүлэх | **7 (2.3%)**; хариулах 5/224 |

**Дүгнэлт.** Ижил A7 тохиргоонд асуулт төгс англи байвал 21.3% (64/300) — **монгол хэл ба домэйны мэдлэгийн дутагдал** гол
саад (≈10 дахин ялгаа). Цаашдын бүх алхам A7-ийн SQLite → PostgreSQL хөрвүүлэлт дээр суурилна.

## 2. RAG — домэйны мэдлэгийг prompt-д нэмэх (B бүлэг): 2.3% → **14.3%** (+12.0 хувь)

RAG = асуулт бүрт хамааралтай мэдлэгийг хайж prompt-д оруулах. Дөрвөн эх сурвалж (бүгд `build/index/`-д индексжүүлсэн):

1. **Схемийн тайлбар (B1)** — `knowledge/semantic_model.yaml`: 28 view, багана бүрийн **монгол/англи тайлбар, синоним, enum-ийн
   код ба монгол нэр** (жишээ: `BROKEN = Биелээгүй`). DDL-д SQL comment болж орно (`loan_number TEXT -- Зээлийн дугаар (LN-…)`).
   Мөн «мэдлэгийн тэмдэглэл»: өнөөдрийн огноо, олон валютыг `*_mnt` баганаар нэгтгэх дүрэм.
2. **DB-ийн утгын хайлт (B2)** — DB-ийн текст баганын давтагдахгүй утга бүр (≈1 100 утга; ID/дугаарын багана хасагдсан)
   кирилл түлхүүр, сул латин түлхүүр, галиг хувиргалттай индекс. Асуултын үг/хэллэгийг (1–3 үг) BM25 n-gram-аар тааруулж
   `Stored value 'Дархан салбар' exists in branches.branch_name` мэт 10–20 мөрийг evidence болгоно — загвар утгыг DB-д
   бичигдсэнээр нь хуулахын тулд.
3. **Бизнес нэр томьёо (B3)** — `knowledge/glossary.yaml`: NPL хувь, PAR30, идэвхтэй багц, зөвшөөрлийн хувь… бүр **монгол
   тодорхойлолт + каноник SQL**-тэй. Асуултад хамгийн ойрын 4 нэр томьёог evidence болгоно.
4. **Few-shot жишээ (B4)** — асуулт + gold SQL хосын сан (`knowledge/examples*.jsonl`, эхэндээ 160). DAIL маягаар: асуултын
   утга/нэрийг маскжуулаад хамгийн төстэй 3–5 жишээг prompt-д үзүүлнэ.

**Хайлтын арга.** Hybrid: **BM25 + bge-m3 embedding** (жин 0.5) — хүснэгт, нэр томьёо, жишээг эрэмбэлнэ; асуулттай холбогдсон
хүснэгтүүдийг (linked tables) сонгож схемийн текстийг токены төсөвт багтаана.

**Дүн.** B5 (B1–B4 бүгд) = **14.3% (43/300)**, A7-аас +12.0 хувь (p ≤ 2·10⁻⁷).

## 3. Нэмэлт сургалт — LoRA (C, D бүлэг): 14.3% → 15.7% (+1.4); boolean засвар 19.3% (+3.6)

- **C бүлэг** (RAG-гүй SFT: rejection sampling, CoT, өөрийн синтетик өгөгдөл) — суурийг эвдсэн (C1 3.0%, C2 2.7%, C3 10.0%).
  RL-ээр сургасан загварыг өөр хэлбэрийн prompt-оор сургах нь хор хөнөөлтэй.
- **D2** — B5-ийн RAG-тай prompt-ийн хэлбэрээр **LoRA** (rank 32, α 64, бүх linear давхарга, LR 2·10⁻⁴, 2 epoch; A100 дээр bf16,
  T4-д fp16 болгон нэгтгэсэн). dev **15.7% (+1.4)**. Нэмэр бага байсан шалтгаан: өөрийн DB-ийн 344 жишээ бүгд prompt-ийн уртаас
  болж сургалтаас хасагдсан (ижил кодоор 82 → 81 — ялгаагүй). Иймд эцсийн системд **«d2» adapter-ийг нэгтгэсэн жингээр** ашиглана.
- **D2 fix** — диалект хөрвүүлэлтийн алдаа: boolean баганыг `= 0/1`-ээр харьцуулдаг байсан (D2-ийн 51 алдааны 31). Засвар →
  **19.3% (+3.6)**.

## 4. Орчуулга (D2 tr, H бүлэг): 19.3% → **36.7%** (+17.4)

- **D2 tr** — асуултыг ерөнхий LLM орчуулагчаар (Qwen3.5-9B) англи руу орчуулж, DB-ийн утгыг placeholder-оор хамгаалсан →
  **27.0% (+7.7)**.
- **H1** — SQL-ийн дараах засвар (схемээс гаргасан алдаа засах), **intent check** (хувийн мэдээлэл, өгөгдөл өөрчлөх хүсэлтээс
  татгалзах), алдаатай SQL-ийг хариулт болгохгүй (abstain).
- **H4** — загварт **зөвхөн англи орчуулга** өгнө, харин RAG-ийн хайлт (утга, нэр томьёо, жишээ) **монгол асуултаар** (монгол
  тайлбар, утгатай мэдлэгийн санг бүрэн ашиглах), жишээг англиар харуулна → **36.7% (110/300)** (+9.7 D2 tr-ээс); test 34.0%.

**SQL guard (бүх алхамд).** Зөвхөн нэг SELECT/WITH, зөвхөн `t2s` view, аюултай функцийн хар жагсаалт, EXPLAIN-ийн өртгийн
хязгаар, read-only транзакц, timeout.

## 5. Олон хувилбар ба санал хураалт (E бүлэг): 36.7% → **41.0%** (+4.3)

  хамгийн олон хувилбар ялна) → **41.0% (123/300)**, хариулах 44.6%; test 38.5%.
