## 2. Офлайн шинжилгээ (DEV)

### 2.1 Prompt-ийн урт ба зөв эсэх

- H4-ийн жинхэнэ `prompt_tokens` (vLLM): медиан **20 090**, хүрээ 19 524–20 730. Схем тогтмол (28 хүснэгт) тул хэлбэлзэл
  ердөө ~1.2k токен. Энэ хэлбэлзлийг юу үүсгэдэг вэ: жишээний SQL-ийн урт (r = 0.82), асуултын урт (0.59), утгын хит (0.35).
- Квартилаар (H4): Q1 51%, Q2 35%, Q3 33%, Q4 27%. H1: 39 / 20 / 16 / 9%. D2+tr: 51 / 25 / 29 / 25%.
- **Гэхдээ энэ нь голдуу хүндрэлээс үүдэлтэй.** Урт prompt нь урт/хэцүү асуулттай давхцдаг (gold SQL-ийн урт ба prompt-ийн r = 0.58).
  Gold-ын уртыг хянасан хэсэгчилсэн корреляци: prompt ↔ зөв **−0.10**, жишээний SQL-ийн урт ↔ зөв **−0.01**.
  → **Одоогийн 19.5–20.7k-ийн хүрээнд** prompt-ийг бага зэрэг уртасгах нь бие даасан хор хөнөөл бараг үзүүлэхгүй.
  Харин 20k ↔ ~6–9k (schema linking) харьцуулалтыг энэ өгөгдлөөр үнэлэх боломжгүй.
- Анхааруулах зүйл: `orchestrator.schema_text`-ийн төсөв (`schema_token_budget: 6000`) нь `est_tokens()` ойролцоо тоолуураар
  тоологддог. Би H4-ийн prompt-ийг офлайн дахин угсрахад `est_tokens` ≈ 6.9k гарсан (схем ≈ 5.8k). vLLM-ийн тоо ≈ 20k.
  Энэ ~2.9 дахин зөрүү нь (а) ойролцоо тоолуур кирилл/SQL-ийг дутуу тоолж байгаа, эсвэл (б) миний угсралт run-ийнхаас ялгаатай
  гэсэн үг. Аль нь болохыг токенизаторгүйгээр ялгах боломжгүй (**баталгаагүй**). Хэрэв (а) бол «6000 токены төсөв» нь бодитоор
  ~17k болно. Энэ нь D2-ийн сургалтаас 16 384-өөс урт prompt-ийг хассан (WORKLOG §6) явдалтай зөрчилдөнө:
  M1a-ийн inference prompt нь **D2-ийн сургалтын тархалтаас гадуур** байж болзошгүй.
- Схемийн текстийн 34% нь кирилл үсэг (баганын монгол тайлбар). Гэтэл `en_prompt` горимд загвар зөвхөн англи асуулт хардаг.

## 4. Шилдэг 3 зөвлөмж

### З1. Хүснэгт мэдэх few-shot сонголт (DAIL-ийн «урьдчилсан SQL» алхмыг хүснэгтийн олонлогоор)
- **Юу:** `ExampleIndex.search`-д `prelim_tables` нэмнэ. Pool 20 → `0.5·асуултын оноо + 0.5·Jaccard(жишээний хүснэгт,
  prelim_tables)`. prelim_tables-ийн эх үүсвэр (хямдаас нь): (а) `linked_tables[:3]` — нэмэлт дуудлагагүй; (б) эхний
  greedy хувилбарын SQL-ийн хүснэгт (RSL-SQL-ийн backward-тэй ижил санаа); (в) чуулгад шинэ гишүүн болгох.
- **Нотолгоо:** cover 67.4 → 78.1% (а) / 79.9% (б); андуурагддаг хосын бохирдол 28 → 16.5%. Хүндрэлээр давхаргалахад
  cover-ийн EX-ийн ялгаа дунд асуултад +16, хүнд асуултад +20 хувь.
- **Хүлээгдэх ахиц: dev хариулах боломжтой асуултаар +2…+5 (баталгаагүй).** ~25 асуулт шинээр cover болно. Ажиглагдсан
  ялгааны 1/3–1/2 нь учир шалтгааных гэж таамаглав. Энэ нь хүнд/cross-domain асуултад хамгийн их нөлөөтэй.
- **Зардал:** код ~30 мөр, 1 dev run (M1a-тай ижил, 1 хувилбар ≈ 1 цаг T4). (б) нь 2 дамжлагатай тул хугацаа ×2.
- **Эрсдэл:** урьдчилсан SQL буруу хүснэгттэй бол алдааг бэхжүүлнэ. Иймээс (б)-д gold-гүйгээр `linked ∪ prelim`-ийг
  ашиглах ба M1a-тай хамт чуулгад оруулах нь аюулгүй. Мөн BM25-only нь hybrid-ээс cover-оор илүү гарсан (70.5 vs 67.4) тул
  `hybrid_alpha`-г жишээнд тусад нь dev дээр тааруулж болно.

### З2. Schema linking + FK-гүүрийг 7B-д бодитоор туршиж, токены төсвийг жинхэнэ токенизатороор тоолох
- **Юу:** Бэлэн `M1s2`-тэй ижил тохиргоо (`schema_linking: true`, `fk_bridge: true`, D2, MADLAD кэш) dev run.
  `schema_text`-ийн төсвийг vLLM-ийн токенизатороор (эсвэл кирилл/SQL-д тохируулсан коэффициентээр) тоолох.
  Баганыг хасахгүй (2025-10 оны засвар: багана хассанаар gold багана 45% алдагдсан).
- **Нотолгоо:** prompt одоо ~20k жинхэнэ токен, D2-ийн сургалтаас >16k prompt хасагдсан (тархалтаас гадуур). Linked + FK-гүүр
  нь gold-ыг 99.1% хамарч, схемийг ~40–45% хүртэл богиносгоно. Ном зохиол хоёр талтай: CHESS (~+2%, токен ×5 бага), RSL-SQL
  (+1.2), харин том загварт ашиггүй [`maamari_2024_death_schema_linking`, `chung_2025_long_context_nl2sql`].
- **Хүлээгдэх ахиц: −2…+4 асуулт (баталгаагүй).** Prompt ~2–2.5 дахин богиносч, хугацаа ба T4-ийн санах ойд шууд ашигтай
  (8 хувилбартай run-д чухал). Ахиц бага байсан ч чуулгын **бие даасан алдаатай** шинэ гишүүн болно.
- **Эрсдэл:** linked-д gold хүснэгт алга 0.9% (FK-гүүртэй) – 2.7% (FK-гүүргүй). Dev-ийн шийдвэрийн дүрмээр (McNemar) л батална.

### З3. Хэлний хувьд нэгэн төрлийн, ялгаатай (contrastive) схемийн тайлбар
- **Юу:** `en_prompt` горимд `_col_comment`/`render_ddl`-ийн хүснэгт ба баганын тайлбарыг **англиар** өгөх (semantic model-д `en`
  бий). Монгол синонимыг зөвхөн retrieval-д үлдээх. `table_hints.yaml`-ийн 14 хосын ялгааг evidence мөрөнд биш, тухайн
  хүснэгтийн DDL толгойд `-- not for X; use Y for ...` хэлбэрээр шилжүүлэх (CHESS/M-Schema-ийн «тайлбарыг схемийн дэргэд»).
- **Нотолгоо:** схемийн тэмдэгтийн 34% нь кирилл. Кирилл нь ойролцоо тоолуураар ч 1.5 дахин их токен шаарддаг. Загвар англи
  асуулт хардаг. Андуурлын 4 гол хос нь хүснэгт андуурсан мөрийн ~1/3-ийг бүрдүүлдэг (ACCURACY_PLAN: 198/609; §2.3). XiYan-д тайлбар + жишээ утгатай
  хагас бүтэцтэй схем DDL-ээс дунджаар +2.0 EX өгсөн (том загвар).
- **Хүлээгдэх ахиц: 0…+3 асуулт (баталгаагүй)** + схемийн токен ~25–30% бага (тооцоо, баталгаагүй). M1th-ийн туршилттай
  давхцах тул M1th-ийн dev дүнгийн дараа шийднэ.
- **Эрсдэл:** D2 нь монгол тайлбартай prompt-оор сургагдсан. Тайлбарын хэлийг солих нь сургалтын тархалтаас холдуулж
  болзошгүй. Чуулгын гишүүн болгон туршина.

**Дараалал:** З1(а) (хамгийн хямд, GPU 1 run) → З2 (бэлэн тохиргоо) → З3. Бүгдийг **зөвхөн dev** дээр сонгож, test-ийг эцэст нь
нэг удаа.

## 5. Хязгаарлалт
- Жишээний шинжилгээ `build/index` (160)-аар хийгдсэн. M1a-д `index_plus_dev` (160 + шинэ + dev) ашиглагддаг тул
  cover-ийн суурь өндөр байж магадгүй. Тэр санг локалд байхгүй тул шалгаагүй.
- Симуляци BM25-only (bge-m3-ийн embedding локалд кэшлэгдээгүй, татаагүй). Бүртгэгдсэн hybrid-тэй яг ижил биш.
- Корреляцийн дүнгүүд учир шалтгааныг батлахгүй. Ахицын тоонууд бүгд **баталгаагүй**.
- 7B-д pruning туслах тухай «Qwen2.5-7B full 37.1 → retrieved 40.2» гэсэн тоо хайлтын хураангуйд гарсан ч эх хуудсанд
  олдоогүй — ишлэхгүй.
