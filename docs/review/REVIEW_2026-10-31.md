## 3. Кодын олдвор ба засвар

Зарчим: одоо байгаа тохиргооны анхдагч гаралт өөрчлөгдөхгүй; шинэ зан төлөв нь анхдагчаар унтраалттай сонголт
(`_LATE_DEFAULTS`) эсвэл зөвхөн алдааны/вэб замд.

**Сервис (src/mn_text2sql/service, db/executor.py, security/sql_guard.py)**
- C1 (ноцтой): flow-ийн замын сонголтоор (glossary_file, glossary_select_cache, index_dir) серверийн дурын файлыг уншуулж,
  алдааны мессежээр агуулгыг нь харах; /dev/zero-оор глобал түгжээг гацаах → knowledge/ эсвэл build/ доорх энгийн файл л,
  хэмжээний хязгаартай; Pipeline түгжээн дор угсрагдахгүй; ерөнхий алдааны мессеж (request id).
- H1: нэг ажлын хэмжээ хязгааргүй → candidates ≤ 16, rounds ≤ 5, agent_max_steps ≤ 8, repair_workers ≤ 8, fewshot_k ≤ 10,
  pool ≤ 50; граф ≤ 50 node; body ≤ 256 KB; /flow/compile, /feedback rate limit.
- H2: `repeat('x', 1e8)` мэт үр дүн вэб процессын санах ойг дүүргэх → `Executor(max_result_bytes)` (вэбд 5 MB, server-side
  cursor, `too_large`); eval-ийн зам өөрчлөгдөөгүй. Үлдэгдэл эрсдэл: нэг мөр PostgreSQL-ийн ~1 GB хүртэл.
- M1, L3–L6: adapter/dataset зөрүүгийн анхааруулга; flow-ui-д trusted-Host; auth-ийн docstring; /health; feedback-ийн урт.
- Guard: `ts_stat`, `ts_rewrite`, `crosstab*`, `connectby`, `xpath_table` (дурын SQL мөр гүйцэтгэдэг) хориглогдсон.
- Executor-ийн error_code: хаагдсан холболт → `connection`, бусад Python exception → `client_error`; SQL алдаа хэвээр.

**Pipeline (orchestrator.py, intent_check.py, options.py, llm/client.py)**
- intent_check-ийн буруу татгалзал: `өөрчил` нь «бүтэц өөрчилсөн зээл»-д, `и-?мэйл` нь «Имэйл сануулга»-д, англи `regist`
  нь «registered»-д таарч татгалздаг (test L058 — D2 зөв, H4/I3t/E4 татгалзсан). → `intent_rules: v2` (анхдагч legacy;
  WEB/WEBA-д идэвхтэй): мэдлэгийн сангийн шошгыг маскалж, бичих **хүсэлтийн** хэлбэрийг л тооцно. Dev mn-ийн шийдвэр
  өөрчлөгдөхгүй; жинхэнэ татгалзал бүгд хэвээр (dev 13/13, test 5/5).
- Тохиргооны шалгалт: үл мэдэгдэх `--set`/`--var` түлхүүр, буруу enum/bool утга одоо алдаа (өмнө чимээгүй алгасаж, хуучин
  run-ийн файлыг «шинэ хувилбар» гэж үргэлжлүүлдэг байсан).
- C8 (`select_parse: strict`): `select_raw_full`, offline дахин parse; «none»/тоо/зураасны дүрэм.
- C4 (`repair_strict`): HTTP статустай `LLMCallError`; түр алдаа → infra; bool_cols → `InfraError`; M1ks сонгогч ба
  adaptive давалгааны түр алдаа → infra.
- Oracle горимд SQLite→PG хөрвүүлэлт алгасна.

**Үнэлгээ (eval/)**
- Gold-ийн амжилтгүй гүйцэтгэлийг кэшлэхгүй, timeout/холболтод нэг дахин оролдоно, `gold_error` тэмдэг (оноо хэвээр);
  холболтын алдаа → infra (дахин асууна), 3 сессээс хэтэрвэл `error_stage="infra"`.
- Тасарсан сүүлийн JSONL мөр → `<run>.jsonl.partial`, resume-ийн өмнө засна; бичлэг нэг бичилтээр.
- Abstention curve-ийн TrustSQL бүх ангиллаар; `.meta.json`-д кэш/adapter-ийн хэш; code_digest-ийн хүрээ (config,
  knowledge) ба session бүрийн жагсаалт; `pick` сүүлийн `<answer>`; adaptive симуляторын EX_нийт runner-тэй ижил (fixed8
  48.47 → 52.62 = бодит E4 53.00-тай таарна; `docs/ADAPTIVE_SAMPLING.md` шинэчлэгдсэн); ансамблийн зардлын талбар.
