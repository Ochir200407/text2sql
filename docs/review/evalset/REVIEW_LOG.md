# Eval set — хоёр дахь (бие даасан) шалгалт ба засварын бүртгэл

Зааврын дүрэм: gold SQL-ийг хоёр хүн шалгана. Эхний шатанд 8 зохиогч агент бичиж, `check-gold` давуулсан (0 алдаа).
Хоёр дахь шатанд бие даасан 4 хянагч агент зөвхөн уншиж, gold бүрийг bot эрхээр дахин ажиллуулсан. Тэд асуултын
утга, хувилбар, ангилал, мета, жишээний сангийн давхардлыг шалгаж, тайлан бичсэн. Хянагчид файл өөрчлөөгүй. Засварыг
lead хийж, дараа нь `check-gold`-оор дахин баталгаажуулсан (660 бичлэг, 0 алдаа; A045-ийн alt_sql-ийн зориудын
анхааруулга 1).

| Хянагч | Хамрах хүрээ | HIGH | MEDIUM | Гол олдвор |
|---|---|---|---|---|
| r1 | loans, payments (+ жишээ) | 0 | 13 | L032 огноо/EARLY_FULL-ын хоёрдмол утга; P012-ийн хамрах хүрээ (хассан зээл); P056-ийн валютын хөрвүүлэлт; 3 жишээ eval-тэй ижил загвартай |
| r2 | applications, customers (+ жишээ) | 1 | 13 | A045: бөөрөнхийлсөн утгаас LAG тооцсон (0.01 зөрүү); огнооны тодорхойгүй байдал (ирсэн/шийдвэрлэсэн); код↔нэр баганын хатуу харьцуулалт |
| r3 | collection, deposits (+ жишээ) | 0 | 13 | «хаагдаагүй ↔ open cases» орчуулга; сул хоёрдмол (K050, D054); 5 жишээ eval-тэй ижил загвартай |
| r4 | gl_trends, cross (+ жишээ) | 3 | 30+ | G046-ийн валют; G049-ийн үндэслэл; X059 ↔ X014/X030/X031 «хугацаа хэтэрсэн»-ийн зөрчилтэй шошго; cross-ийн хялбар асуултууд бусад домэйны давхардал |

## Хэрэгжүүлсэн шийдвэр

**Set-wide дүрэм.**
- Хариулах боломжтой асуулт хоёрдмол нэр томьёог тайлбаргүй хэрэглэхгүй:

  | Үг | Шийдвэр |
  |---|---|
  | «хугацаа хэтэрсэн» | «(1+ хоног)» нэмсэн: X014, X030, X031, GX09, L033, LX07 |
  | «идэвхтэй зээл» | «идэвхтэй багцын зээл» болгосон: K046, X009, X016, X017, X023, X024, X029, X037, X038, X045, XX01, XX07, XX09, XX18 |
  | «хүүгийн орлого» | «ерөнхий дэвтэрт бүртгэсэн» нэмсэн: G032, GX18 |

  Тайлбаргүй хэлбэр зөвхөн хоёрдмол асуултад үлдсэн (X059, G048, K053, K054, P056, G046, P062).
- `contains_value` / `values` нэг дүрмээр дахин тогтоогдсон (81 бичлэг). Дүрэм: gold SQL-ийн WHERE-д DB-ийн чөлөөт
  текст утга (нэр, дугаар) байвал тэмдэглэнэ. Semantic model-ийн enum код ба огноог тооцохгүй.
- Файл хоорондын ихэр асуултыг нэг family-д нэгтгэсэн. Ингэснээр dev/test-д хуваагдахгүй:
  - G001, G046 ↔ P056;
  - G049 ↔ G028, G048 ↔ G008, G052 ↔ G009, G051 ↔ G040;
  - G057, X052 ↔ L054; X058 ↔ X017;
  - L006/L026, P008/P031/P032, L035/L045;
  - K001/K003/K014, K015/K017/K031, D016/D020/D030, D021/D032;
  - A015/A042, A016/A040, C003/C037, C006/C034, C016/C028.

**Evaluator.** Хянагчдын саналаар уян харьцуулалт нэмсэн. Хатуу хувилбарыг тусад нь тайлагнана (`docs/EVAL.md`):
- хугацааны бүлэг: сарын огноо ↔ 'YYYY-MM' ↔ сарын дугаар;
- код ↔ нэр.

## Үлдсэн хязгаарлалт

- Чөлөөт текст утга (салбар, бүтээгдэхүүн, аймгийн нэр, дугаар) агуулсан хариулах боломжтой асуулт цөөн: ~30 / 375.
  F2/F3 (бичиг хоорондын утга тааруулалт)-ын статистик хүчийг нэмэхийн тулд нэмэлт «утгын» probe set гаргахыг зөвлөж
  байна.
- Generator-ийн бодит бус зарим онцлог (жишээ: скоринг зөвшөөрөлд бараг нөлөөлдөггүй, хаагдсан салбарт идэвхтэй
  зээл үлдсэн) нь хувиргасан snapshot-ийн нэг хэсэг. Eval set тэдгээрийг харгалзан бичигдсэн.
