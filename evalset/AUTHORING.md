# Eval set бичих заавар (дэд агентуудад)

Энэ нь монгол хэлний Text2SQL системийн **үнэлгээний асуултын сан**-г бичих заавар. Зорилго: 500 асуулт
(300 dev / 200 test), асуулт бүр кирилл, латин галиг, англи хувилбартай, gold SQL нь бодит DB дээр
гүйцэтгэгдэж шалгагдсан. Дүрмийн эх сурвалж: `docs/guide/GUIDE.md` (6-р хэсэг) ба
`docs/guide/EXPERIMENT_PLAN.md` («Туршилтын дүрэм»).

## 1. Орчин

- DB: PostgreSQL, ББСБ (банк бус санхүүгийн байгууллага). Bot зөвхөн **`t2s` схемийн 28 view**-г харна.
- Схем, багана бүрийн монгол/англи тайлбар, enum утгын утга: `knowledge/semantic_model.yaml` — **заавал уншина**.
- KPI, нэр томьёоны каноник тодорхойлолт: `knowledge/glossary.yaml` — **gold SQL эдгээрийг дагана**.
- **Өгөгдлийн "өнөөдөр" = 2026-06-30** (`t2s.business_date()`). `CURRENT_DATE`, `now()` нь үнэлгээнд
  энэ огноо руу автоматаар солигдоно. Өгөгдөл 2024-01-01-ээс 2026-06-30 хүртэл (зарим харилцагч 2016-аас).
- Утга шалгах (bot role-оор):
  ```bash
  cd C:/Users/ochir.b/Desktop/claude/text2sql-new
  export PYTHONPATH=src T2S_ADMIN_DSN="postgresql://postgres@localhost:55432/postgres" PYTHONIOENCODING=utf-8
  python scripts/dev/sql.py "SELECT branch_code, branch_name FROM t2s.branches ORDER BY 1"
  ```
- Gold шалгах: `python -m mn_text2sql check-gold evalset/drafts/<файл>.jsonl` → `errors` 0 болтол засна,
  `warnings`-ийг (tie, хэт олон мөр) аль болох арилгана.

## 2. Бичлэгийн формат (JSONL, нэг мөр = нэг асуулт)

```json
{"id": "L001", "family": "L-f01", "domain": "loans", "category": "answerable", "difficulty": "medium",
 "question_mn": "Дархан салбарын хугацаа хэтэрсэн зээлийн тоо хэд вэ?",
 "question_latin": "Darhan salbariin hugatsaa heterssen zeeliin too hed we?",
 "question_en": "How many overdue loans does the Darkhan branch have?",
 "question_mixed": null,
 "gold_sql": "SELECT count(*) FROM t2s.loans l JOIN t2s.branches b ON b.branch_id = l.branch_id WHERE b.branch_name = 'Дархан салбар' AND l.is_active_portfolio AND l.days_past_due > 0",
 "alt_sql": [], "order_matters": false,
 "tags": ["join", "value", "glossary"], "contains_value": true, "values": ["Дархан салбар"],
 "glossary_terms": ["overdue_loan"], "notes": ""}
```

- `id`: домэйны үсэг + 3 оронтой дугаар (давхардахгүй). `family`: ижил загвар/хувилбарын бүлэг — ижил
  family-ийн асуултууд dev эсвэл test-ийн аль нэгэнд л орно. Ихэнх асуулт өөрийн family-тэй; хувилбар (утга
  солисон, өөрөөр асуусан) хамгийн ихдээ 3 нэг family-д.
- `category`: `answerable` | `unanswerable` | `ambiguous`.
- `difficulty` (answerable дотор зорилтот харьцаа **30% easy, 50% medium, 20% hard**):
  - easy — нэг view, энгийн шүүлт/тоолох/нийлбэр.
  - medium — 1–2 JOIN, GROUP BY/HAVING, огнооны логик, CASE, хувь.
  - hard — 3+ JOIN, дэд асуулга/CTE, window функц, хоёр үеийн харьцуулалт, ранк, шилжилт.
- `tags`: `join`, `aggregation`, `group_by`, `having`, `date`, `window`, `subquery`, `cte`, `ratio`,
  `top_k`, `distinct`, `case`, `value`, `glossary`, `multi_currency`, `null_handling`, `time_series`.
- `contains_value` / `values`: асуултад DB-ийн текст утга (салбарын нэр, бүтээгдэхүүн, аймаг, барьцааны
  төрөл ...) орсон эсэх ба тэдгээр утга (DB-д бичигдсэнээр нь).
- `order_matters`: асуулт эрэмбэ шаардсан үед л `true` (ранк, "эрэмбэл", top-k).

### Хариултгүй (`unanswerable`, ~12%)
`gold_sql: null`, `unanswerable_reason`:
- `pii` — регистр, утас, гэрийн хаяг, имэйл, дансны дугаар, батлан даагчийн нэр гэх мэт view-д байхгүй хувийн мэдээлэл;
- `missing_data` — схемд огт байхгүй өгөгдөл (ажилтны цалин, салбарын түрээс, харилцагчийн сэтгэл ханамж, ROE, өрсөлдөгчийн мэдээ);
- `non_sql` — SQL биш даалгавар (гэрээ бичих, имэйл зохиох, бодлого зөвлөх);
- `external_knowledge` — гадны мэдлэг (Монголбанкны бодлогын хүү, инфляци, хуулийн заалт);
- `future` — таамаг (ирэх оны NPL хэд болох вэ);
- `write_operation` — өгөгдөл өөрчлөх хүсэлт (зээлийн хүүг өөрчил, бичлэг устга).
Асуулт нь итгүүштэй, DB-тэй ойрхон байх ёстой (жишээ: "Зээлийн мэргэжилтнүүдийн дундаж цалин хэд вэ?").

### Хоёрдмол утгатай (`ambiguous`, ~13%)
`gold_sql: null`, `clarification_mn` (тодруулах нэг асуулт), `interpretations`: 2–3 ширхэг
`{"label_mn": "...", "sql": "..."}` — **тайлбар бүр өөр үр дүн өгөх ёстой** (check-gold шалгана).
Эх сурвалж: glossary-ийн `ambiguous` хэсэг (идэвхтэй зээл, хугацаа хэтэрсэн, үлдэгдэл, хүүгийн орлого,
дундаж хүү, хэвийн зээл, идэвхтэй харилцагч), бүдэг үг ("хамгийн том харилцагч" — зээлээр үү,
хадгаламжаар уу), бүдэг хугацаа ("сүүлийн 3 сард": сүүлийн 90 хоног уу, 4–6-р сар уу).

## 3. Gold SQL-ийн дүрэм

1. PostgreSQL 14-д нийцтэй, **зөвхөн `t2s.<view>`** (схемийн нэрийг заавал бич), ганц SELECT/WITH.
2. KPI-г **glossary-ийн каноник тодорхойлолтоор**: идэвхтэй багц = `is_active_portfolio`; хугацаа хэтэрсэн =
   `is_active_portfolio AND days_past_due > 0`; PAR30/PAR90, NPL хувь — үндсэн үлдэгдлээр (`principal_outstanding_mnt`);
   зөвшөөрлийн хувь — glossary-ийн томьёо. Каноник бус утгаар асуух бол асуултад тодорхой бич эсвэл ambiguous болго.
3. Олон валют: зээл/хадгаламжийн дүнг нэгтгэхдээ `*_mnt` багана (асуулт нэг валютаар хязгаарласан бол түүгээр).
4. **Асуусныг яг гарга**: илүү багана бүү нэм. Асуулт нь юуг гаргахыг тодорхой хэлэх ёстой ("салбарын нэр ба
   зээлийн тоог гарга", "дүнг хэл"). Жагсаалтад ID биш нэр/дугаар (branch_name, loan_number, product_name) гарга.
5. Детерминизм: LIMIT-тэй бол ORDER BY + **давхардахгүй нэмэлт түлхүүр** (жишээ: `ORDER BY amount DESC, loan_number`).
   Текстээр эрэмбэлж LIMIT хийхээс зайлсхий (collation ялгаатай байж болно).
6. Хувь: `ROUND(…, 2)` болно (харьцуулалтын хүлцэл 0.01). Мөнгөн дүнг бүхэл тоо руу бүү бөөрөнхийл.
7. Огноо: тодорхой үе илүү ("2025 оны 4-р улирал", "2026 оны 3-р сар"). Харьцангуй хугацааны конвенц:
   "энэ сар" = 2026-06; "өнгөрсөн сар" = 2026-05; "энэ жил/оны эхнээс" = 2026-01-01..2026-06-30;
   "өнгөрсөн жил" = 2025; "сүүлийн 30 хоног" = `> CURRENT_DATE - 30`; "өнөөдрийн байдлаар" = одоогийн төлөв.
8. Хариултгүй/хоосон үр дүн бүхий answerable асуулт бүү бич (check-gold алдаа гаргана). Гүйцэтгэл < 3 сек.
9. Хэрэв үр дүн мянга мянган мөр бол асуултыг нэгтгэсэн/шүүсэн болго (тайланд хэрэгтэй хэмжээ).

## 4. Асуултын хэл

- **Кирилл (`question_mn`)** — үндсэн. Банк бус санхүүгийн байгууллагын шинжээч, менежер, барагдуулагчийн
  бодит асуух хэв маягаар: албан ("…-ийн тоог гаргана уу"), ярианы ("хэдэн зээл хэтэрсэн бэ"), тушаах
  ("жагсаа", "гарга"), асуух ("хэд вэ?"), товч ("Дархан PAR30"). Нөхцөлийн нөхцөл, дагавар олон янз:
  "Дархан салбарын", "Дарханд", "Дархан салбараас", "Эрдэнэтийнх". View/баганын нэрийг асуултад бүү бич.
  DB-д байгаа утгыг ашигла (утгыг скриптээр шалга).
- **Латин галиг (`question_latin`)** — хэрэглэгч гар утсаар бичдэг шиг, кирилл үсэггүй. Хоёр хэв маягийг
  холино: (а) ~60% "v/u/w" хэв маяг — ү→v, ө→u, в→w, х→h, ы→ii, й→i (жишээ хэрэглэгчийн өөрийн бичвэрээс:
  "zuwhun" = зөвхөн, "bvh" = бүх, "hvr" = хүр, "awna" = авна, "baihlaar" = байхаар); (б) ~40% "u/o/v" хэв маяг
  — ү→u, ө→o, в→v, х→kh/h, ц→ts. Нэр, утгыг ч галигаар: "Darhan salbar", "Bayanzurh", "Songinohairhan".
  Заримдаа товчлох, тэмдэггүй бичих ("hed we", "heden zeel bn").
- **Англи (`question_en`)** — утгыг яг дамжуулсан энгийн орчуулга.
- **Холимог (`question_mixed`, ~15%)** — англи/орос банкны нэр томьёо холилдсон ("Дархан салбарын NPL ratio хэд вэ",
  "overdue зээлүүд", "кредит портфель"). Бусад үед `null`.

## 5. Жишээний сан (few-shot pool)

Тусдаа файлд (`<domain>_examples.jsonl`) ~20 бичлэг, ижил формат, `category: answerable`, нэмэлт
`"pool": "examples"`. **Eval асуултын хувилбар/давтлага биш** өөр загварын асуулт байна (тест рүү
мэдээлэл алдагдахаас сэргийлнэ). Эдгээр нь DAIL маягаар few-shot болон сургалтад ашиглагдана.

## 6. Ажлын дараалал

1. semantic_model.yaml, glossary.yaml-ийг уншиж, өөрийн домэйны view-үүдийг судал (утгууд, хэмжээ).
2. Асуултуудаа бичиж `evalset/drafts/<domain>.jsonl`-д хадгал. Gold-ыг скриптээр ажиллуулж үр дүнг
   нүдээр шалга (утга нь бодит асуултын хариулт мөн үү).
3. `check-gold`-ийг ажиллуулж бүх алдааг зас.
4. Дуусахдаа товч тайлан: тоо (category, difficulty), тулгарсан асуудал, DB-ийн сонирхолтой баримт.
