Энэхүү ажлаар нэг GPU-д ажиллах нээлттэй эхийн Arctic-Text2SQL-R1-7B загварт суурилсан, банк бус санхүүгийн
байгууллагын өгөгдлийн сан дээр монгол хэлээр асуусан асуултыг SQL болгож хариулдаг системийг бүтээж, бүрэлдэхүүн бүрийн
нөлөөг хяналттай туршилтаар хэмжив.

Шинэ асуултаас бүрдсэн test дээр (dev-ээр сонгосон тохиргоо; хаалтад гол хэмжүүр болох хариулах боломжтой EX) нэмэлт
сургалттай суурь (D2) 21.0\% (24.5\%) байсан бол орчуулга ба засвартай H4 34.0\% (31.8\%), 8 хувилбарын санал хураалт ба
дүрэмтэй E4 45.0\% (42.4\%; dev-д дэмжлэгтэй түлхүүр үгээр нийт 43.0\%) хүрэв. H4-ийн нийт ахиц ач холбогдолтой
($p = 8.6\times10^{-4}$) боловч хариулах боломжтой асуултад батлагдаагүй ($+26/-15$, $p = 0.12$): ахицын ихэнх нь татгалзал
ба тодруулгаас гарсан. Dev дээр мэдлэг хайлт (+12.0 хувь) ба ижил кодоор хэмжсэн орчуулга (+7.7) хамгийн их, өөрийн DB-ийн
жишээгүй нэмэлт сургалт (+1.4; ижил кодоор 82 → 81) ба алдааны мессежээр засах (+0.3) хамгийн бага нэмэр өгсөн. Алдааны
38\% нь орчуулгаас үүдсэн тул санхүүгийн хэллэгийн орчуулгын өгөгдөл бэлтгэж, орчуулагчийг нэмж сургав: 2 828 хосын
өгөгдлөөс бэлтгэсэн 8 601 мөрөөр QLoRA сургасан MADLAD-400-3B-ийн chrF++ 53.5 → 74.8 (Qwen3.5-9B 58.0) болж, түүгээр
орчуулсан нэг үүсгэлттэй тохиргоо (M1a) dev-ийн хариулах боломжтой асуултад 56.7\% буюу Qwen орчуулгатай I3t-ээс 9.8 хувь
өндөр гарсан ($+40/-18$, $p = 0.0054$); test дээр хариулах боломжтой асуултад 41.1\% → 53.6\% ($+32/-13$, $p = 0.0066$),
нийт 101/200 (50.5\%) болсон. Гэвч M1-ийн сургалтын өгөгдөлд test-ийн орчуулгын алдааны шинжилгээнээс гарсан нэр томьёо
орсон тул нөлөөлсөн 13 асуултыг хасахад ахиц 59 → 72 ($+25/-12$, засваргүй $p = 0.047$), few-shot санд бараг ижил SQL
загвартай 6 асуултыг ч хасахад 57 → 66 ($+21/-12$, $p = 0.16$) болж test дээр батлагдахгүй (§\ref{sec:validity}). Харин
M1a ба түүний дөрвөн хувилбарын (M1ks, M1g8, M1m, M1rr) SQL-ийг гүйцэтгэлийн үр дүнгээр санал хураадаг,
урьдчилан зарласан эцсийн систем M1ens-ийг test дээр нэг удаа хэмжихэд нийт 110/200 (\textbf{55.0\%}), хариулах боломжтой
90/151 (\textbf{59.6\%}) зөв хариулж, M1a-аас $+10/-1$ ($p = 0.012$) илүү гарсан бөгөөд дээрх 13 ба 6 асуултыг хасахад ч
ахиц хэвээр ($+8/-1$, засваргүй $p = 0.039$); dev дээрх ахиц ($+11/-1$, $p = 0.006$) давтагдаж, dev ба test-ийн зөрүү бага
байв (хариулах боломжтой 61.2\% → 59.6\%, §\ref{sec:final-test}). Гишүүдийн аль нь ч дангаараа M1a-аас илүү гараагүй тул
хамгийн сайн ганц тохиргоо нь M1a (50.5\%), урьдчилан зарласан эцсийн систем нь M1ens; dev-ийн дүрэм нэмсэн M1ensr-ийн
60.0\% нь dev-ийг харж тааруулсан дүрэм ба dev-д тохиолдоогүй түлхүүр үгээс хамаардаг тул гол дүн биш. Сэдэв
батлах даалгаврын зорилтуудын биелэлтийг Хүснэгт~\ref{tab:goals-met}-д нэгтгэв.

\textbf{Оруулсан хувь нэмэр.} (1) Монгол хэлний Text2SQL-ийн 500 асуулттай үнэлгээний сан; (2) бага нөөцтэй хэл ба 7B
загварт мэдлэг хайлт ба орчуулга хамгийн их нөлөөтэйг харуулсан эмпирик нотолгоо (орчуулгыг ижил кодоор McNemar
тестээр; мэдлэг хайлтын A7 → B5-д асуулт бүрийн гаралт хадгалагдаагүй ч нийт 7 → 43 тул ямар ч хослолд
$p \leq 2.1\times10^{-7}$); (3) алдааны эх
үүсвэрийн хэмжилт ба орчуулгын өгөгдөл; (4) үнэгүй үүлэн квот дээр давтагдахуйц систем ба Text2SQL Studio хэрэгсэл.

\textbf{Цаашдын чиглэл.} Test-ийн нийт EX одоо урьдчилан зарласан эцсийн систем M1ens-д 55.0\% (хариулах боломжтой
59.6\%), хамгийн сайн ганц тохиргоо M1a-д 50.5\% байна. Dev-ийн дүрэм нэмсэн M1ensr 60.0\% авсан ч дүрмийг dev-ийг харж
тааруулсан, хоёр түлхүүр үг нь dev-д тохиолдоогүй тул энэ тоо өөдрөг; хос харьцуулалтын нэмэр test дээр хэмжигдээгүй.
Доорх ажлыг хүлээгдэх нөлөө ба зардлаар эрэмбэлэв.
«Бэлтгэсэн» гэж тэмдэглэсэн ажлын код ба тохиргоо бэлэн боловч GPU дээр үнэлээгүй тул нарийвчлалд үзүүлэх нөлөө нь
хэмжигдээгүй.
\begin{enumerate}
  \item \textbf{Сургасан хос сонгогч.} Тохиргоонууд өөр өөр асуултыг зөв хариулдаг: dev-ийн хариулах боломжтой асуултын
        146/224-ийг дөрвөн тохиргооны аль нэг нь зөв хариулсан бол чуулга (M1ens) 137/224-т хүрсэн; test дээр ч таван
        гишүүний аль нэг нь зөв хариулсан 102/151 асуултаас чуулга 90-ийг сонгосон. Иймд CHASE-SQL
        \cite{pourreza_2024_chase_sql}, XiYan-SQL \cite{liu_2025_xiyan_sql}, JudgeSQL \cite{bai_2025_judgesql}-ийн адил
        гүйцэтгэлээр шошголсон хувилбарын хосоор сонгогч сургаж, dev дээр чуулгатай McNemar-аар харьцуулна.
  \item \textbf{Hidden state дээрх хариулах боломжгүй асуултын ангилагч.} Татгалзалт одоо dev-ийн хэллэгээс бичсэн
        дүрэмд тулгуурладаг. Бэлтгэсэн ерөнхий шинжүүдийн логистик регресс (abstain v2) dev-ийн family-аар хуваасан
        cross-validation-д 154.5 $\pm$ 1.7 зөв хариулт авч, in-sample дүрмийн 159-ийг давсангүй; дүрэмтэй хослуулахад
        160.9 $\pm$ 1.0 болсон. Иймд LatentRefusal \cite{ren_2026_latentrefusal}-ийн адил загварын завсрын hidden state
        дээр хөнгөн ангилагч сургах нь дараагийн алхам.
  \item \textbf{CTE/задаргааны генератор (бэлтгэсэн: M1cte).} Хэцүү, CTE, харьцааны асуулт хамгийн сул тул дэд алхмыг
        \tsql{WITH}-ээр төлөвлүүлдэг заавартай генераторыг DIN-SQL \cite{pourreza_2023_din_sql}-ийн санаагаар чуулгын
        шинэ гишүүн болгоно. Одоогийн гишүүд ижил prompt-той тул алдаагаа давтдаг; нөлөөг dev дээр хэмжээгүй.
  \item \textbf{Хүснэгт ялгах сануулга (бэлтгэсэн: M1th).} Буруу хариултад төстэй хүснэгтийг андуурах (жишээ нь
        \tsql{loan\_writeoffs} ба \tsql{loan\_payments}) түгээмэл тул semantic model-оос бичсэн 14 хосын сануулгыг
        prompt-д нэмнэ. FK замаар завсрын хүснэгт нэмэх аргыг (FK-bridge) мөн бэлтгэсэн боловч dev-ийн 97.3\%-д gold
        хүснэгт prompt-д аль хэдийн байдаг тул нөлөө бага байх төлөвтэй. Аль алиных нь EX-ийн нөлөө хэмжигдээгүй.
  \item \textbf{Өөрийн схемийн синтетик өгөгдөл ба LoRA-г дахин сургах.} Semantic model-оос 7 хэв маягаар 2\,779
        асуулт--SQL хос үүсгэсэн; гүйцэтгэлээр шүүх, rejection sampling хийх, D3-ийг дахин сургах алхмууд үлдсэн.
        Шүүгээгүй синтетик өгөгдөл нарийвчлалыг бууруулж болохыг Arctic-Text2SQL-R1 \cite{yao_2025_arctic_text2sql_r1}
        харуулсан тул SING-SQL \cite{caferoglu_2025_sing_sql}, OmniSQL \cite{li_2025_omnisql}-ийн адил шүүлтийг заавал
        хийж, dev дээр synth-гүй сургалттай харьцуулна.
  \item \textbf{Бодит өгөгдөл ба хэрэглэгчийн лог.} DB ба асуултууд синтетик. Бодит өгөгдлийн хамгаалалттай хуулбар
        дээр shadow горимоор туршиж, Studio-ийн үнэлгээгээр цугласан, хүн хянасан асуулт--SQL хосоор үнэлгээний ба
        жишээний санг баяжуулна; үнэлгээний санг хоёр домэйн шинжээчээр шалгаж, латин асуултыг тусад нь хэмжинэ.
  \item \textbf{Хариултын хугацааг бууруулах.} 8 хувилбартай тохиргоо T4 дээр асуулт бүрт $\sim$3 минут зарцуулдаг бол
        эцсийн M1ens таван гишүүн тохиргооныхоо нийлбэр хугацааг шаарддаг (§\ref{sec:latency}). Санал нийлэлт хангалттай үед хувилбар үүсгэхийг эрт зогсоох, орчуулга ба мэдлэг хайлтыг
        кэшлэх, илүү хүчтэй GPU ашиглах замаар бодит хэрэглээнд тохирох хугацаанд хүргэнэ.
\end{enumerate}

\textbf{Нийгмийн нөлөө.} Монгол хэлээр өгөгдлийн сангаас тоо мэдээ авах боломж нь SQL мэдэхгүй ажилтнуудын шинжээчээс
хамаарах хамаарлыг бууруулж, шийдвэр гаргалтыг хурдасгана. Нээлттэй эхийн загвар ба нэг GPU-д суурилсан тул жижиг, дунд
байгууллага ч өгөгдлөө гадагш гаргахгүйгээр ашиглах боломжтой.
